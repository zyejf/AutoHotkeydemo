# 技术债清理实施计划（2026-09-16）

> 目标：**以技术债清理为核心**，在不改变对外可观测行为的前提下，把本仓库的
> 「可度量债项」清零到约定水位，并建立防复发机制。
>
> 本文所有数字均来自 2026-09-16 对本仓库的实测（见 §1.1），不是估计值。
> 债项明细与状态追踪在 `docs/tech-debt-register.md`（台账），两文件互相引用。

---

## 0. 前置：本计划的四条硬约束

| 约束 | 内容 | 违反后果 |
|---|---|---|
| **C1 行为保持** | 任何重构不得改变对外可观测行为（定义见 §4.1）。无法证明「行为没变」的 PR 一律不合并 | 停止该 PR |
| **C2 单 PR 单主题** | 禁止「重构 + 行为变更」混提；单个 PR ≤ 400 行；基线类文件（`baselines.json`）单独 PR 并注明来源 | 打回拆分 |
| **C3 可回滚** | 每个 PR 必须能被 `git revert` 独立撤销且不连带其它改动 | 打回 |
| **C4 先有网再动刀** | 若目标代码没有自动化覆盖，**先补测试再重构**（本仓库 T1/T6 的 oracle 范式见 §4.2） | 顺序颠倒即打回 |

### 1.3 量化评估维度与排序规则

**收益侧（各 1–5 分）**

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| **I** 影响面 | 单文件内部 | 单模块 / 单 crate | 跨语言（Rust↔AHK↔JS）或对外契约 |
| **P** 恶化速度 | 静止，不修也不变差 | 缓慢累积 | 每次改动都放大（如文档漂移、被复制传播） |
| **V** 可验证性 | 只能人眼评审 | 有测试可回归 | 有等价性 oracle / 可脚本自动判定 |
| **S** 战略对齐 | 纯美观 | 影响开发效率 | 阻塞后续工作 / 误导决策 |

**成本侧**

- **C** 成本（人天，斐波那契取值 0.5 / 1 / 2 / 3 / 5 / 8）
- **R** 风险系数：低 **1.0**（可脚本验证、无运行时影响）／中 **1.4**（改生产代码路径）／高 **2.0**（跨语言契约、无覆盖）

**优先级指数**

```
DPI = (I + P + V + S) / ( √C × R )
```

> 用 `√C` 而非 `C`：否则大成本项会被过度惩罚，而「便宜的小修」会挤占全部 P0。
> 取 √ 后既能让「低成本高收益」排前，也不至于把基础设施级缺口压到末位。

| 档位 | DPI | 处置 |
|---|---|---|
| **P0** | ≥ 10 | 立即做，且优先做（含「1 小时内可闭环」的快赢项） |
| **P1** | 5 ~ 10 | 本轮清理内必须完成 |
| **P2** | 2 ~ 5 | 排入下一轮，或随相关功能改动顺带做 |
| **P3** | < 2 | 登记观察，不主动做 |

**硬性升档规则（不看 DPI，直接 P0）**

1. 安全 / 数据丢失 / 崩溃风险；
2. **误导性文档**（会让人照着做错事，如 M11 的不可达目标）；
3. 阻塞他人或其他任务开工；
4. 已被证明会产生 flaky CI 的项。

**降级规则（不看 DPI，直接降级）**

1. 已确认是**刻意保留**的（读 MEMORY.md / AGENTS.md 确认）—— 例：`*Legacy` 旧实现是等价性 oracle、
   `AutoHotkey-2.0.26/` 是只读引擎源码参考 → 先补「勿删」标记，不按死代码处理；
2. 收益依赖尚未确认的外部信息（如无产品 SLO、不知 joystick 是否主力功能）→ 登记待定。

## 2. 分阶段执行路径

> 统一约定：每阶段以「四闸门全绿 + 本阶段验收项」为出口；**每阶段结束写一个 commit 里程碑**，
> 便于整体回退到阶段起点。
> 工作量按「1 名熟悉本仓库的开发者」估算（含验证与文档同步）。

### 阶段 0 · 度量与基线（2.5 人天）

| 项 | 内容 |
|---|---|
| **目标** | 让「技术债」从主观判断变成**脚本可判定**的数字 |
| **交付物** | ① `docs/tech-debt-register.md`（台账）；② `scripts/check-tech-debt.ps1/.sh` 三检：`重复/未引用文件检测`、`未注册测试文件检测`、`文档-代码一致性检测`（K 值、测试计数、基线来源）；③ 当前基线数字快照（写进台账「基线」列） |
| **验收** | 脚本可执行且输出 0 号基线；三检各自的检测项有**阳性对照**（人为造一个债，脚本必须报出来） |
| **回滚** | 纯新增文件，删除即回滚；不碰任何生产代码 |
| **依赖** | 无 |

### 阶段 1 · 止血：死代码与文档漂移（4 人天）

| 项 | 内容 |
|---|---|
| **目标** | 清掉「明显是债且删了不会有人反对」的部分，并修掉会误导决策的文档 |
| **范围** | TD-001（快照移出 docs）、TD-002（测试文件注册或删除）、TD-003（删根 `ui_manager.ahk`）、TD-011（K 值，已完成）、TD-013（`tests/legacy/json.ahk` 1469 行，确认无引用后处置）、F 类 M11/T13 目标订正 |
| **交付物** | 每个债项一个独立 commit；`scripts/check-tech-debt` 的三检接入四闸门 G3/G4 |
| **验收** | ① 重复文件数 = 0、未注册测试文件 = 0、文档-代码不一致项 = 0（脚本判定）；② 四闸门全绿；③ AHK 用例数**不变**（664 / CI 657+7） |

## 3. 质量门禁

### 3.1 测试与覆盖率（可度量水位）

| 对象 | 当前 | 目标水位 | 强制方式 |
|---|---|---|---|
| Rust 纯逻辑 crate（domain / ipc-protocol / application）行覆盖 | 未知，**阶段 0 先测出基线** | ≥ 80%（若基线 < 60%，阶段 3 先到 60%，再逐季 +10%） | `cargo llvm-cov --fail-under`，**阶段 2 末转阻断** |
| Rust src-tauri 主 crate | 无采集 | 不设水位（Linux 不可编译），靠集成测试 + E2E | — |
| AHK | 664 用例，通过率 100% | 保持 100%；新增模块必须配套套件 | G3 阻断 |
| JS | **0** | 行覆盖 ≥ 40% → 逐季 +10% → 70% | 阶段 3 末转阻断 |
| E2E | 53 用例，CI 默认关 | 连续 5 次通过后转默认开 | 稳定前非阻断 |

> ⚠️ **覆盖率水位不得靠「删测试」或「加 `#[ignore]`」达标** —— CR 检查项第 7 条。

### 3.2 静态分析与 lint

| 语言 | 现状 | 阶段 2 目标 |
|---|---|---|
| Rust | `cargo fmt --check` + `clippy`（四闸门内） | 新增 `clippy.toml`；按组启用 `pedantic` 子集；`cargo fmt --check` 保持阻断 |
| AHK | 无 linter | 阶段 0 的三检脚本（重复/未引用/未注册/文档一致性）；**不引入第三方 AHK linter**（生态不成熟） |
| JS | 无 | 引入 eslint（flat config）+ `npm run lint` 进 CI 阻断 |

### 3.3 Code Review 检查清单（PR 模板必填，10 条）

1. **行为是否改变？** 若改了，是有意为之还是重构副作用？（对照 §4.1 可观测行为清单）
2. **怎么证明行为没变？** 给出具体手段：等价性 oracle / golden 对比 / 差分测试 / 基准门禁。答不出 → 打回。
3. 是否引入新的跨层依赖？（分层 depth：`infrastructure 0 → domain 1 → application 2 → presentation 3 → entry 4 → executor 5 → tests 6 → other 7`，后四者豁免）
4. 是否新增跨 crate 依赖？若是，是否同步更新 `ALLOWED_CRATE_DEPS` 并写明理由？
5. 纯逻辑 crate 是否引入了 `tauri` / `tokio` / `interprocess` / `windows`？（**禁止**）
6. 是否触碰 `watchdog.rs` 的 `STALE_PROCESS_NAMES`？（**只允许 `asd_executor.exe`**）
7. 覆盖率是否下降？是否靠忽略/删除测试达标？
8. 新增开关/常量是否有单测钉住默认值？（参照 `Test_MergeTickScan_DefaultOn_And_DispatchHonorsIt`）
9. 是否同步了文档？（`test-map.md` 数字、developer-guide、AGENTS.md 妥协白名单）
10. 单个 PR 是否 ≤ 400 行、单主题、可独立 revert？

### 3.4 CI 强制通过矩阵

| Job | 当前 | 目标 | 说明 |
|---|:--:|:--:|---|
| 四闸门 G1 图谱基线 | 阻断 | 阻断 | 无新增环 / 无白名单外违规 |
| 四闸门 G2 fmt + clippy | 阻断 | 阻断 | 零告警 |
| 四闸门 G3 测试 + test-map 对账 | 阻断 | 阻断 | 数字必须与 `test-map.md` 一致 |
| 四闸门 G4 文档同步 | 人工 | **阶段 1 后自动化**（三检脚本接入） | 消除人工核对 |
| AHK 生产基准（T11） | 阻断 | 阻断 | 8 档 ≤ 基线 ×K |

| 依赖 audit | 无 | **阶段 2 新增，阻断** | `cargo audit` + `npm audit` |

## 4. 行为保持约束

### 4.1 「对外可观测行为」清单（变更任何一条 = 行为变更，需显式批准）

| # | 契约 | 现有守护 |
|---|---|---|
| 1 | IPC 协议报文格式（`asd-ipc-protocol`） | Rust 单测 + fuzz target（5 个） |
| 2 | 配置文件格式（`src-tauri/config.json` roundtrip） | `config_compat_tests.rs` |
| 3 | AHK executor 命令集与响应格式 | `tests/test_ahk_executor/*` |
| 4 | 按键定刻时序语义（周期/序列/混合） | 7 条宿主时延断言（**CI 跳过**，本机跑）+ T11 基准 |
| 5 | 退出码、IPC 错误码语义 | 单测 |
| 6 | UI 可交互行为 | E2E（**CI 默认关** → 阶段 3 治理） |

### 4.2 回归验证手段（四道，按优先级取用）

1. **等价性 oracle（首选，本仓库已有成熟范式）**
   保留旧实现作为比对基准：`JSONSerializer._EscapeStringCharByChar` 守 T1、
   `Sender._ExecutePeriodicLegacy` / `_ExecuteHybridLegacy` 守 T6。
   ⚠️ **这些 `*Legacy` 实现是刻意保留的 oracle，不是死代码，禁止当技术债删除**
   （它们是 `bench_prod_tick` 的 `equiv,...diffs=0` 自检和 `Test_TickMerge_*` 的依据）。
2. **Golden / 快照逐字节对比**：序列化输出、配置 roundtrip、JSON 转义结果。
3. **差分测试**：old/new 同输入比对状态推进（T6 现成做法）。
4. **性能前后对比**：`tools/ahk-bench/gate.py` 归一化门禁（见 §4.4）。

### 4.3 灰度与回退（三档）

| 档 | 适用 | 做法 | 回退方式 |
|---|---|---|---|
| **开关灰度** | 有新旧两条实现路径 | 参照 `MERGE_TICK_SCAN`：默认开、**可一键置回 false**、单测钉住默认值 | 改一个静态字段 |
| **配置灰度** | 行为参数 | 配置项 + 默认值不变 | 改配置 |
| **提交灰度** | 无开关的纯重构 | 单 PR ≤ 400 行、单 commit 单逻辑变更 | `git revert <sha>` |

### 4.4 性能回归门禁（防「重构让代码变快但变错 / 变慢」）

- 判据：`p50 中位数 ≤ 基线 × K`，K 按各 bench 信噪比分别定
  （`prod_escape` **1.5** / warn 1.25；`prod_tick` **1.4** / warn 1.2）。
- **p50 是归一化值**（÷ 同进程紧邻测得的参考负载）：共享 runner 上绝对毫秒跨 run 散布达
  3.7~3.9×，绝对值基线会既误报又漏报（详见 `developer-guide.md` §4.6.4）。
- 任何影响 `JSONSerializer._EscapeString` / `Sender._ExecutePeriodic` 的 PR，T11 必须绿。

## 5. 防复发机制

### 5.1 编码规范（沉淀到 `AGENTS.md`，不新开文档）

| 规则 | 自动化 |
|---|---|
| 分层依赖方向固定，禁止逆向边与环 | `scripts/check-graph-baseline.py` |
| 新增跨 crate 依赖须同步 `ALLOWED_CRATE_DEPS` 并写理由 + 到期日 | 图谱基线检查 |
| 纯逻辑 crate 禁 `tauri`/`tokio`/`interprocess`/`windows` | clippy / 人工 CR 第 5 条 |
| 旧实现作 oracle 时必须在文件头标注「⚠️ 等价性 oracle，勿删」 | CR 第 8 条 |
| 新债项必须先登记台账才能延期 | 台账 PR 模板钩子 |

### 5.2 架构约束自动化

- `scripts/check-gates.ps1/.sh`：一键四闸门（本机等价 CI）。
- `scripts/check-tech-debt.ps1/.sh`（阶段 0 新增）：重复/未引用文件、未注册测试、文档-代码一致性。
- pre-commit hook（`scripts/hooks/` 已有）：阶段 1 后把三检接入。

### 5.3 技术债台账（`docs/tech-debt-register.md`）

字段：`ID | 类别 | 描述与证据 | I/P/V/S/C/R | DPI | 档 | 状态 | 负责人 | 计划阶段 | 实际完成 | 备注`

- **状态**：`待评估 / 已排期 / 进行中 / 已完成 / 豁免（附理由+到期日） / 待定（缺外部信息）`
- **硬性要求**：任何「不修」的债项必须落到 `豁免` 或 `待定` 并写明理由，**不允许静默消失**。
- **入口**：新增债项 = 开 PR 改台账，不允许只在聊天里提一句。

### 5.4 定期复盘

| 周期 | 内容 | 产出 |
|---|---|---|
| 每次 PR | CR 清单 10 条 | PR 描述勾选 |
| 每周 | 台账 P0 项清点；flaky 统计（同 commit 重跑结果不同即计一次） | 周报一行 |
| 每月 | DPI 重算（成本/风险可能变化）；覆盖率水位；flaky 率趋势；豁免项到期复审 | 台账更新 + 下月计划 |
| 每季 | 覆盖率水位上调评审；阶段目标达成度 | 计划文档更新 |

## 6. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| CI flaky（本轮已吃 3 次：宿主时延、IPC 均值、基准误报） | 门禁失去公信力 | 新门禁**先跑 5 次全绿**再转阻断；结论必须跨轮可复现 |
| 共享 runner 性能不可判定 | 误报/漏报 | 已用归一化解决；**不得**改回绝对毫秒阈值 |
| AHK v2 无成熟 linter / 覆盖率工具 | 阶段 3 可能做不动 | 阶段 3 先做 1 人天预研，出结论即止 |
| 删错「看起来像死代码」的东西 | 功能丢失 | 删除前必须做全仓库反向引用搜索并在 PR 留证据；疑似 oracle 的一律先查 MEMORY.md/AGENTS.md |
| E2E 环境不稳定是环境限制 | 投入打水漂 | 保持非阻断，达标才转默认开 |
| 41 人天投入 vs 产品需求冲突 | 计划停摆 | 阶段 0–2（13.5 人天）优先保障，其余可分段 |
