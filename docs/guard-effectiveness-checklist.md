# 守护有效性清单（Guard Effectiveness Checklist）

> 配套：`.github/workflows/ci.yml`（四闸门 + 独立 job）、`scripts/check-*.py`、`scripts/run-standalone-ahk-tests.sh`。
> 建立日期：2026-09-18。本文件回答的不是「有哪些门禁」，而是 **「每个门禁现在还灵不灵」**。

## 一、为什么需要这份清单

本仓出现过四次同一形态的事故：**守护存在、看起来在跑，但它防的不是它声称防的东西**。
四次都不是读代码发现的，都是「第一次真正执行」才暴露的：

| # | 实例 | 形状 | 代价 |
|---|---|---|---|
| 1 | AHK `tests/` 下 7 个独立脚本从未被任何 runner 执行 | B | 首次接入连挖 **TD-034/035/036** 三个生产 BUG |
| 2 | `tests/test_joystick.ahk` 未接入套件 | B | 33 条断言首次执行，当场暴露 TD-017 |
| 3 | E2E 一直在跑 2026-06-29 编译的旧 `asd_executor.exe` | C | 产出 **12 条假 HIGH**，被当成真缺陷登记 |
| 4 | `test_webview2_bridge.ahk` 被 OnError 吞错、静默空转 | C | 38 条断言从未执行；揭穿后 2 条立刻红 → **TD-047 生产 BUG** |

**核心洞察：代价排序是「假阳性 > 静默失效 > 通道腐烂」。**
死守护只是不报警；**假守护会主动产出假信号、消耗人力、并掩盖真 BUG**（TD-047 就是被第 3 例盖住的）。
它还会训练出最坏的习惯：看到红先点重跑、`--update-baseline` 无脑过。

## 四、最该优先查有没有失效的 3 个

1. **G3f 覆盖率棘轮** —— 唯一「度量型守护却没有范围锚点」。基线平台（Windows）与执行平台（ubuntu）不一致，且文件从 lcov 消失不触发任何判定。若 `--package` 列表被改小，它会**无声缩范围并可能继续报绿**。补一个「基线文件必须全部出现在本次 lcov」的缺失检查 + 文件数下限，成本约十几行。
2. **G4 文档同步** —— 结构上不可能失败（纯 `Write-Host`）。它同时挂着「棘轮收紧水位」与「`ALLOWED_CRATE_DEPS` 同步」两件要紧事，等于**这两件事目前无人守**。至少要给其中可静态判定的项（如 `ALLOWED_CRATE_DEPS` 与 `Cargo.toml` 实际依赖的一致性）配一个真闸门，其余保留人工。
3. **G3h watchdog** —— 观测期 `continue-on-error` 且**无截止日期**。它是本轮刚从 A 类（15 条 `#[ignore]`）救回来的守护，最容易在忙碌中永远停在「观测期」。建议立刻给它定到期日与转硬门禁的判据（本机与 CI 各连续 **≥10 次全绿**、含 `--test-threads=1`；2026-09-19 三处已统一为该最严口径，由 `check-test-map.py` 的 F2 段校验）。

> 同类次优（本期未列前三）：**G3c** 的范围萎缩无下限锚点（`src/__tests__` 若被改名会无声缩小）；**G2b** 的 `#[allow]` 局部失效是否有人兜（待核实）；**技术债台账评分列**无自动校验（见上表末行，与 G4 同性质：登记了但没人验）。

> 一个共性观察：G4、台账评分列、E2E 通道这三处，都是「**有一个东西在那儿，但没有任何机制能证明它有效**」。本清单存在的意义就是让这类东西**从不可见变成可见** —— 只要它被登记并写明「判据：无」，它就不再是隐藏风险。

## 五、复查规则（建议，待 team-lead 确认后生效）

任何「排除 / 跳过 / ignore / 外部产物依赖」登记时必须带两条腿，**缺一不可**：

- **`expires`（时间维度）**：到期即红 —— 防「攒着不管」。复用本仓已有机制：`check-graph-baseline.py:95-121`（理由非空 + 合法 ISO 日期）、`:384-386`（缺失或过期 → 硬失败）。
- **阳性对照（有效性维度）**：改坏即红 —— 防「到期前一直在假装有效」。本仓已在 TD-051（PC-1/2/3）、TD-046（旧 exe 在场 → FATAL）、TD-047（降级值改回空 Map → 3 条全红）、`check_extra_exclude_rules` 防永真锚点上四次验证有效。

只有 `expires` 没有阳性对照 = 只在日历上提醒复查，复查的人仍无从判断它现在还灵不灵。

登记格式（每条三行）：

```
- 对象：<排除 / 跳过 / ignore / 外部产物>
  expires: 2027-03-18
  阳性对照：<一条能把它打红的命令或改动> → 期望：<变红> → 已复验：<日期>
```
