> 一句话结论：**共享工作区 + 长构建 + 无标记 = 必然事故。**

---

## 0. 先定性：这不是「某人操作失误」

写成人，下次换个人还会犯；写成机制，才有得改。三条理由：

1. **提交者做的是正常提交。** 他提交的是 `test(watchdog): 补 GiveUp 门控的测试，并让 spawn 重试可观测`——与变异体毫无关系的正当工作。他**没有任何理由**去读 `lib.rs` 的 diff。
2. **施加者做的是正当实验。** 变异测试的前提就是「把代码改坏，看门禁会不会红」。这一步本身不能省。
3. **双方都没有信息表明对方在场。** 没有任何通道告诉他们「此刻有人在写同一个文件」。

⇒ 缺的是**机制**，不是纪律。纪律在时间足够长时的失效概率是 1；机制才有 0。

### 1.1 为什么门禁抓不到（这条比时间线更重要）

变异点是**覆盖盲区**——这正是选它做变异的理由：

- `lib.rs:766` 的 `if true` 使 `else` 分支（`lib.rs:768-777`，TD-089 新增的两级快照诊断）成为**死代码**；
- 按 `release-pipeline-2026-09-20.md` §2 层②：快照**格式化函数本体**有单测，但**两处调用点的接线没有任何测试**；
- ⇒ 变异生效后，**全部门禁保持绿**（`cargo test` / `clippy` / `check-tech-debt.py` 全部 rc=0）；
- ⇒ 唯一的检测器是**有人恰好去读那个文件的 diff**。这次是运气。

**若未被发现**：TD-089 会被记为「已验证」，而它的诊断实际是死代码；下一次资源缺失事故的日志**静默无输出**——正是 TD-089 存在的意义所要消除的那种「伪装」。且该变异体会随 release 包分发出去。

## 2. 为什么「跑完立刻还原」这条规矩不够

这条规矩的方向是对的，但它**优化错了变量**。

**冲突的不是文件，是时间窗。**

- 变异必须存在于**工作树**——测试跑的是工作树，不是 index，也不是 HEAD。所以「把变异藏起来」在技术上不可能。
- release 构建要 **3–4 分钟**（本仓实测 3m23s）。⇒ 变异体在共享工作区**必然停留数分钟**。
- 这几分钟里，**任何人**的 `git add -A` / `git add <该文件>` / `git commit -a` 都会把它扫走。而提交者的**意图与变异体无关**，他没有任何动机去看那个文件的 diff。
- 「跑完立刻还原」缩短的是**我这一侧的时延**；它**不能**降低「别人的提交落在我的窗口内」的概率。窗口不为 0，事故就是时间问题，不是概率问题。

### 2.1 连「还原后再 diff 一次」也不够

`release-pipeline-2026-09-20.md` §3 提的第二条（**还原后必须「提交后再 diff 一次」才算完成**）防的是「我以为还原了其实没还原」。它**防不了**本事故：本次是**队友的提交先于我的还原**——我 diff 时看到的是干净的工作树，而变异体已经在 git 历史里了。它假设了「我能控制提交顺序」，而共享工作区里这个假设不成立。

## 3. 新规矩三条

### 规矩 1 · 变异体停留期间，文件顶部加标记

- Rust：`// ⚠️ MUTANT — 勿提交（施加者 / 预计还原时刻）`
- PowerShell：`# ⚠️ MUTANT — 勿提交`
- **还原时删标记**。判据：**标记还在 = 未还原**，不依赖任何人的记忆。

**为什么放顶部**：`git diff` 的 hunk 头、编辑器打开的第一屏、`git add -p` 的第一块，都能一眼看到。中间位置的注释会被折叠掉。

**可核对判据（不是口号）**：提交前 `git diff --cached` 出现 `MUTANT` 即阻断。可落成 pre-commit hook，也可人工；**关键是有一步「去查」的动作**，而不是「记得」。

### 规矩 2 · 开工前在群里声明：文件 + 预计时长 + 还原判据

三要素缺一不可：

| 要素 | 作用 |
|---|---|
| **哪个文件** | 队友据此避开 |
| **多久** | 给队友一个明确的时间窗，而不是「不知道要多久」 |
| **怎么算还原完** | 可核对（标记删掉 + 该文件 `git diff` 为空），不靠「我说还原了」 |

这是**让别人能避开**的唯一手段——他不知道你在改，他就无法避开。

### 规矩 3 · 队友活跃期，不在别人会提交的文件里留未提交改动

- **默认做法：变异改副本。** `cp` 到独立目录 + 独立构建，共享工作树全程干净。
- 改共享文件**只在「独占窗口」下允许**，而独占窗口必须是**声明出来的**（规矩 2），不是默认状态。

## 4. 同一根因的三次事故

| 事故 | 时刻 | 形态 | 同一个机制 |
|---|---|---|---|
| **变异体入库**（本复盘） | 03:31:47 | 工作树里的中间态被别人的提交扫走 | 共享工作区 + 长任务 + **无标记** |
| `--amend` 误伤（`d84813c`，见 §9） | 02:45 前后 | 想改 A 的提交信息，实际命中当时也在提交的 B | 共享工作区 + 并发写 ref |
| 冒烟脚本被整份覆盖 | 09-20 | 两人同时落笔同一文件，一版加固被整份覆盖 | 一个文件两个落笔人 |

三条是同一件事的三个面：**仓库只有一个工作区、一个 ref，而我们的隐含假设是「同一时刻只有我一个人在写」。**

⇒ 上位规矩：**任何「中间态」（变异体 / 半成品 / 临时改动）都必须显式声明并加标记；否则默认它就是会被别人提交的内容。**
