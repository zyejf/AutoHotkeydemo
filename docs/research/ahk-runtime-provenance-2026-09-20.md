# AHK 运行时的来源策略：可复现性与完整性（2026-09-20，**第二版**）

**关联：** TD-090（本轮订正）、TD-089、TD-074、TD-081、TD-086
**状态：** 决策建议（未走 ADR 流程，理由见 §6）
**范围：** 只出结论与建议。**未修改 `tauri.conf.json` / `Cargo.toml` / 任何构建脚本。**

> ⚠️ **本版相对初版有一处定性订正**：初版写「干净 checkout（含 CI）无法构建」，**不成立** —— CI 有下载步骤可以构建。问题收窄为「**干净本地 clone 构建失败**」+「**下载产物无完整性校验**」。三方案的 Effort 与推荐理由随之调整。

## 1. 事实（实读实证，2026-09-20 复核）

| # | 事实 | 取证 |
|---|---|---|
| F1 | `asd_executor.exe` 与 `AutoHotkey64.exe` **均未入库** | `git ls-files` 对两者**零命中** |
| F2 | 二者都是**本地构建产物** | `.gitignore:35` 的 `*.exe` 排除；`ahk_executor/` 内只有 `.gitkeep` |
| F3 | `bundle.resources` 只列 `AutoHotkey64.exe`(:44) 与 `asd_executor.bat`(:45)，**未列 `asd_executor.exe`** | `tauri.conf.json:37-48` |
| F4 | **CI 有 4 处同名步骤**「准备 ahk_executor 的 AHK 运行时资源」 | `ci.yml:129 / 580 / 725 / 981`（`:981` 在发布构建 job 内，run 35466724544 实测绿） |
| F5 | 该步骤把上一步安装的 AHK 复制到 `ahk_executor/AutoHotkey64.exe`，**版本钉死 `2.0.26`** | 上一步 `holy-tao/install-autohotkey@v2.1.0` 的 `version: '2.0.26'`（5 处） |
| F6 | **下载产物无完整性校验** —— 步骤只做 `Test-Path` + `Copy-Item` | 全文件 `Get-FileHash` 仅出现于 `ci.yml:1026`，那是给**构建产物**算 SHA256，**不是**校验下载来的运行时 |
| F7 | **本地假绿**：`build.rs` 有缓存指纹、不会重跑 | `ci.yml:134` 的注释（该注释的机制描述比本仓任何一份文档都清楚） |

⇒ **CI 能构建**（F4/F5）。**干净 clone 的本地构建会失败**（F1/F2/F3，报 `resource path ahk_executor\AutoHotkey64.exe doesn't exist`），且**本地长期不显形**（F7）。

**取证边界（不许混）**：F1–F7 均为本次实读实证；**「debug 产物含 / release 产物不含 `asd_executor.exe`」由 Cody 实测、本次未能复核**（本机 `target/*/bundle` 已不存在），不得当已复核事实引用。

## 2. 三条危害（按当前认知排序）

1. **本地假绿（最隐蔽）**：`build.rs` 缓存指纹使其长期不显形，直到有人清缓存或在全新机器上 clone 才炸。
2. **本地与 CI 路径不对称本身就是债**：CI 有兜底、本地没有 ⇒ 同类问题会反复以「在我机器上是好的」的形态出现。**这一条要单独记住** —— 它不随某个文件是否入库而消失，它是一种**结构不对称**。
3. **供应链完整性**：版本钉了 2.0.26，但传输与来源层面无 sha256 校验，而该二进制**最终随安装包分发给终端用户**（GPLv2 第三方二进制，义务见 TD-081）。

**与 TD-089 的关系不变**：TD-089 是「包里少了个文件」，本条是「包里有什么本身就说不清」—— 本条仍是 TD-089 复现与回归验证的**前置**。

**DPI 变化**：初版 8.08 → 本次 **9.29**（I 4→3、P 3→2、S 4→3，但 C 2→1）。**档位仍为 P1**，故台账统计行与状态词表**无需改动**。

## 3. 三个选项（按新事实重判）

### 选项 ① vendor 进 git（LFS 或直存）

| 维度 | 重判 |
|---|---|
| 对「本地干净 clone 可构建」 | **直接解决**：checkout 即得二进制 |
| 对 CI 的影响 | 4 处下载步骤可降级为**校验**；构建更快、更确定 |
| 新风险 | a) 体积约 2.6M（`AutoHotkey64.exe` 1.27M + `asd_executor.exe` 1.34M），相对 `.git` 约 100M 占 2.6% —— **直存可接受**；b) **二进制入 git 无 diff / 无审阅能力**，须配哈希基线（复用 TD-010 的 C6 守卫与 `scripts/vendor-baseline-ahk-2.0.26.txt` 同款机制，**基线须取上游官方而非本地快照**）；c) GPL 合规：入库等于**再分发一份 GPLv2 二进制副本**，与 TD-081 义务叠加；d) **LFS 不划算** —— 为 2.6M 引入 LFS 服务端配额与「clone 需装 git lfs」的持续成本 |

### 选项 ② prebuild 脚本下载 + 校验哈希 —— **工作量比初版估计的小**

> **关键变化**：CI **已经在做前半段**（下载 + 钉版本，F4/F5），缺的只是**后半段（哈希校验）**。所以 ② 不是「新造一套下载」，而是「**给既有步骤补一个校验**」，外加两件顺带的事。

| 维度 | 重判 |
|---|---|
| 实际动作 | a) 给下载步骤补 **sha256 校验**（期望哈希入库，不符即硬失败）；b) 把 **4 处重复的内联步骤收敛为 1 个受版本控制的脚本**（这 4 处本身就是「同一件事抄四遍、改一处漏三处」的病灶）；c) 给**本地**提供同一个脚本作为兜底，消除 F2 那条 asymmetry |
| 对「本地干净 clone 可构建」 | **解决**（靠 c）；且 a 一并修掉危害 3 |
| 对 CI 的影响 | 改动面最小、不改变产物形态；风险是**写错哈希会让 4 个 job 同时红** —— 故哈希必须与版本同批入库、且失败信息要明确指向「哈希不匹配」 |
| 新风险 | a) 构建**必须联网** —— 与 TD-086 的「WebView2 需联网下载」叠加后，**离线构建彻底不可行**，须写进用户文档；b) 上游下架/改址即断构建，URL 与哈希须入库并带到期复查；c) 二进制**未经本仓审阅**，信任转移到上游 + 哈希 |

### 选项 ③ 只留便携模式，删除编译模式分支

| 维度 | 重判 |
|---|---|
| 对「包里有什么说不清」 | **不单独解决** —— 便携模式仍需要 `AutoHotkey64.exe`，而「它不受版本控制」这件事 ③ **没有触及**。⇒ ③ **必须**与 ① 或 ② 组合 |
| 对「本地与 CI 不对称」 | **这条它能解决，而且是收益最大的一步** —— 删掉 `lib.rs:635-643` 的编译模式分支后，本地与 CI 走同一条路径，不再出现「本机有 `asd_executor.exe` 走编译模式、CI 只能走便携模式」 |
| 新风险 | a) 便携模式是**脚本解释执行**，启动耗时/报错行为/包体积与编译 exe 不同，需重测 —— TD-089 的 spawn 路径与冒烟断言 A5/A6 都要**按便携模式重取基线**；b) 属**行为变更**，须先确认确有场景依赖编译模式；c) 将来若要恢复编译模式，产物来源问题原样回来 |

## 4. 推荐（维持「② 然后 ③」，但 ② 的内涵已变）

### 第一步（先做 ②，工作量已缩小）

1. 哈希入库 + 校验（修危害 3，成本最低、风险最可控）
2. 4 处重复步骤收敛为单一受控脚本（顺带消除复制粘贴病灶）
3. 同一脚本供本地使用（修危害 1 与 2）

**理由**：它是唯一**同时**修到三条危害、且**不引入新外部依赖、不改变产物形态**的动作。做完之后「包内清单可枚举」才第一次成立 —— 那是 TD-089 回归验证能开张的最低条件。

### 第二步（再做 ③）

在便携模式被冒烟断言 A5/A6 **实测覆盖之后**再删编译模式分支。**理由**：它消除「同一份源码、两个内容不同的包」这个最刺眼的不一致，但它**依赖第一步先把 `AutoHotkey64.exe` 的来源钉死** —— 顺序颠倒会让第二步失去基准，且它**不能单独**解决本条。

### 不推荐 ①

当前**唯一的实际收益是离线构建**，而这一收益已被 TD-086 抵消 —— 即便 AHK 运行时入库，用户首次安装仍要联网下 WebView2，**离线构建并不带来离线交付**。⇒ 若将来确定需要离线构建再评估；届时**优先直存，不要 LFS**。

## 5. 本轮刻意未做（附理由，勿被当成遗漏）

| 未做 | 理由 |
|---|---|
| 不加 `bundle.resources` 条目 | 会把**不可复现**的产物变成打包**硬要求**，干净构建直接断 |
| 不把 `asd_executor.exe` 设为冒烟必需项 | 会让 CI **每次都红**，而红的原因是环境缺一个从未入库的东西 —— 这正是 npm audit 那步明确反对的**红灯脱敏** |
| 不替团队决定「编译模式 vs 便携模式」 | 发布形态未定；本文档只做权衡与推荐 |
