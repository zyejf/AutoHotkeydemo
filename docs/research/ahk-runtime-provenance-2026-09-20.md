# AHK 运行时的来源策略：打包可复现性（2026-09-20）

**作者：** 系统架构师（阿奇） ｜ **关联：** TD-090（本轮登记）、TD-089、TD-074、TD-081、TD-086
**状态：** **决策建议（未走 ADR 流程）** —— 理由见 §6
**范围：** 只出结论与建议。**本轮未修改 `tauri.conf.json` / `Cargo.toml` / 任何构建脚本。**

---

## 1. 问题（TD-090 的核心，实读实证）

| 事实 | 取证 |
|---|---|
| `asd_executor.exe` 与 `AutoHotkey64.exe` **均未入库** | `git ls-files` 对两者**零命中**（2026-09-20 复核） |
| 二者都是**本地构建产物** | `.gitignore:35` 的 `*.exe` 排除；`ahk_executor/` 内只有 `.gitkeep` |
| `bundle.resources` 只列 `AutoHotkey64.exe`(:44) 与 `asd_executor.bat`(:45)，**未列 `asd_executor.exe`** | 实读 `tauri.conf.json:37-48` |
| `AutoHotkey64.exe` 在 CI 有临时来源、`asd_executor.exe` **没有** | `gates`/`bench`/`release` 三 job 各有一份「准备 ahk_executor 的 AHK 运行时资源」步骤（来源 `holy-tao/install-autohotkey@v2.1.0`，版本固定 2.0.26）。⚠️ 这三份是**复制粘贴式的重复**，不是共享脚本 |

⇒ **任何一个干净 checkout（含 CI）都不可能同时具备这两个文件**，包的内容取决于构建机上恰好有什么，**而不是**仓库内容。

**取证边界（不许混）**：上表四条与「后果②③」为本次实证/直接推导；**「debug 产物含 `asd_executor.exe`、release 产物不含」由 Cody 实测，本次未能复核**（本机 `target/*/bundle` 与 `target/release/bundle` 已不存在）。该条在 TD-090 中已标注为「Cody 实测、未复核」。

## 2. 为什么它比 TD-089 更靠前（但不是更高档）

- TD-089：包里**少了个文件**（`asd_executor.exe`）。
- TD-090：包里**有什么本身就说不清**。

后者是前者的**前置**：在「包内清单不可列举」的前提下，TD-089 的任何复现与回归验证都没有基准 —— 你无法证明「这次比上次多/少了什么」。

| | TD-089 | TD-090 |
|---|---|---|
| C（成本） | 1 | **2** |
| R（风险） | 1.0 | **1.4** |

两者的先后关系体现在**处置顺序**，不体现在档位。

## 3. 三个选项

### 选项 ① vendor 进 git（LFS 或直存）

| 维度 | 评估 |
|---|---|
| 对「干净 checkout 可复现」 | **直接解决**：checkout 即得二进制，包内容与仓库内容一一对应 |
| 对 CI 的影响 | 三处重复的「准备运行时资源」步骤可降级为**校验**而非下载；构建更快、更确定 |
| 新风险 | a) 体积：`AutoHotkey64.exe` 1.27M + `asd_executor.exe` 1.34M ≈ **2.6M**，相对 `.git` 约 100M 只占 2.6% —— **直存可接受**；b) **二进制入 git 无 diff / 无审阅能力**，被替换难以在 review 中发现 —— 必须配哈希基线（可复用 TD-010 的 C6 vendored 纯净性守卫与 `scripts/vendor-baseline-ahk-2.0.26.txt` 的同款机制，且**基线须取自上游官方而非本地快照**）；c) **GPL 合规**：`AutoHotkey64.exe` 是 GPLv2 二进制，入库等于**再分发一份副本**，与 TD-081 的义务叠加（已有 `third-party/AutoHotkey-license.txt` + 三年书面要约，入库不改变义务性质，但让「分发」的事实更明确）；d) **LFS 不划算**：引入 LFS 服务端配额与「clone 需装 `git lfs`」的持续成本，本仓当前**无 LFS 使用痕迹**，为 2.6M 付这个成本不值 |

### 选项 ② prebuild 脚本下载 + 校验哈希（哈希进 git，二进制不进）

| 维度 | 评估 |
|---|---|
| 对「干净 checkout 可复现」 | **可得但不自带**：脚本会去取；可复现性取决于「URL 钉死 + 哈希钉死」—— 二者同时成立时，同一 URL + 同一哈希 ⇒ 同一字节，**内容是可复现的** |
| 对 CI 的影响 | **改动面最小**：CI 现在**已经在下载**（`holy-tao/install-autohotkey@v2.1.0`）并复制到 `ahk_executor/`，本方案只是把这一步从**三处重复的内联脚本**提升为**仓库内受版本控制的单一脚本**，并**补哈希校验** |
| 新风险 | a) 构建**必须联网**，离线/内网构建失败 —— 与 TD-086 的「WebView2 需联网下载」是同一类约束，**叠加后离线构建彻底不可行**，须在用户文档写明；b) 上游下架/改址即断构建，URL 与哈希须一并入库并带到期复查；c) 二进制**未经本仓审阅**，供应链信任转移到上游 + 哈希 |

### 选项 ③ 正式确定只用便携模式，删除编译模式分支

| 维度 | 评估 |
|---|---|
| 对「干净 checkout 可复现」 | **不单独解决**：不再需要 `asd_executor.exe`，但 `AutoHotkey64.exe` 仍须解决 ⇒ 只是把待解决的二进制**从 2 个减到 1 个** |
| 对 CI 的影响 | **收益最大的一步**：删掉 `lib.rs:635-643` 的编译模式分支后，**本地与 CI 走同一条路径** —— 而这正是当前最大的不一致来源（本机有 `asd_executor.exe` → 编译模式；CI 与干净环境只能 → 便携模式） |
| 新风险 | a) 便携模式是**脚本解释执行**，与编译 exe 在启动耗时、报错行为、包体积上不同，需重测 —— 尤其 TD-089 的 spawn 路径与冒烟断言 A5/A6 都要**按便携模式重取基线**；b) 属**行为变更**，须先确认确有场景依赖编译模式；c) 将来若要恢复编译模式，产物来源问题会原样回来 |

## 4. 推荐：**② 然后 ③，分两步**（不推荐 ①）

### 第一步（先做 ②）：把 AHK 运行时的获取脚本化，钉死版本与哈希

- 新增一个受版本控制的脚本（如 `scripts/fetch-ahk-runtime.ps1`），负责取 `AutoHotkey64.exe` 并**校验哈希**；URL、期望哈希、版本一并入库。
- 用它在 CI 里**替换掉三处重复的内联复制步骤**（`gates` / `bench` / `release`）。
- **理由**：改动面最小、不引入新外部依赖、不改变产物形态，且**立刻让 CI 的产物可枚举** —— 这是 TD-089 回归验证能开张的最低条件。
- **附带的收益**：三处重复内联脚本本身就是「同一件事抄三遍、改一处漏两处」的典型病灶，收敛为单一脚本顺带消掉。

### 第二步（再做 ③）：删除编译模式分支，统一本地与 CI 路径

- 在便携模式被冒烟断言 A5/A6 **实测覆盖之后**再删。
- **理由**：它消除的是「同一份源码打出两个内容不同的包」这个最刺眼的不一致，但它依赖第一步先把 `AutoHotkey64.exe` 的来源钉死 —— 顺序颠倒会让第二步失去基准。

### 为什么不推荐 ①（vendor 直存）

2.6M 虽小，但：把 GPLv2 二进制再入一份副本、且二进制无审阅能力。当前阶段**唯一的实际收益是离线可构建**，而这一收益已被 TD-086（WebView2 联网）抵消 —— 即便 AHK 运行时入库，用户首次安装仍要联网下 WebView2，**离线构建并不带来离线交付**。

⇒ 若将来确定需要离线构建，再评估 ①；届时**优先直存，不要 LFS**。

## 5. 本轮**刻意未做**的三件事（附理由，勿被后人当成遗漏）

| 未做 | 理由 |
|---|---|
| 不给 `bundle.resources` 增加 `asd_executor.exe` | 那会把一个**不可复现**的产物变成打包的**硬性要求**，干净构建会直接断（主理人 2026-09-20 裁定） |
| 不把 `asd_executor.exe` 设为冒烟必需项 | 会让 CI **每次都红**，而红的原因是环境缺一个从未入库的东西 —— 这正是 npm audit 那一步明确反对的**红灯脱敏**：因基础设施原因恒红的阻断门禁，会训练所有人忽略红灯 |
| 不替团队决定「编译模式 vs 便携模式」 | 发布形态未定。本文档只做三方案权衡与推荐，**形态决策留给主理人** |
