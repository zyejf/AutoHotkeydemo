本文面向**终端用户**：遇到问题时**不需要懂代码、不需要调内部 API**，按下面的「症状 → 自助处置」走即可。

## 1. 安装阶段问题

### 症状 1.1：双击安装包后「什么也没发生」

**最可能原因**：本应用依赖 **WebView2 Runtime**（Windows 系统 Edge 浏览器用的渲染组件）。安装包默认会去微软官网下载它；如果你电脑**离线**或**被防火墙 / 组策略拦了出站**，就会卡在这里且不报错（NSIS 安装器在「静默下载」模式下不弹窗）。

**自助处置**：

1. **确认是否真的有反应**：打开「任务管理器」看是否有 `MicrosoftEdgeWebview2Setup.exe` 或 `ASD` 安装程序在跑。如果有，在等；如果 30 秒内没动静，**取消它**。
2. **手动安装 WebView2**：从 [微软官网](https://developer.microsoft.com/microsoft-edge/webview2/) 下载 `MicrosoftEdgeWebview2Setup.exe` 或 **Standalone Installer**（离线版），双击装一次。
3. WebView2 装好后，**重新双击本应用安装包**。

> 说明：本应用安装包里写的是 `webviewInstallMode = downloadBootstrapper + silent`（见 `asd-tauri/src-tauri/tauri.conf.json`）。silent 是给最终用户少打扰的设计，但代价就是「没装好也没提示」。本节是给这个设计打补丁的。

### 症状 1.2：安装时报「需要管理员权限」

**最可能原因**：你下载到的是企业版 MSI 安装包（`.msi`），它需要管理员权限。NSIS 安装包（`.exe`）装到当前用户不需要管理员。

**自助处置**：右键安装包 → 「以管理员身份运行」。

### 症状 1.3：安装完成但桌面没图标

**自助处置**：开始菜单搜「ASD」或「技能管理器」；或在文件资源管理器地址栏粘 `%LOCALAPPDATA%\Programs\ASD - 技能管理器\` 双击 `ASD.exe`。你可以右键 → 发送到 → 桌面快捷方式补一个图标。

## 2. 启动与运行阶段问题

### 症状 2.1：双击图标，主窗口一闪而过就消失

**可能原因**：

- 配置文件损坏（上次没正常关闭导致 JSON 不合法）
- 上一进程没杀干净，端口被占（IPC 命名管道重名）

**自助处置**：

1. 进「备份管理」页（如果进得去）→ 看顶部有没有**弹窗**「配置文件未能读取……」 → 按弹窗提示点确定 → 应用自动跳到备份列表 → **恢复最近的备份**。
2. 如果直接崩到桌面、看不到任何 UI：
   - 用任务管理器结束所有 `ASD.exe` / `asd_executor.exe` 进程。
   - 文件资源管理器打开 `%APPDATA%\com.asd.tauri\`。
   - 找到 `config.json`，**重命名**为 `config.json.bak`（不要删，万一备份丢了还能找回来）。
   - 重新启动应用 → 会以**空配置**启动，仪表盘为空。
   - 进「备份管理」 → 选一份最近的备份 → 「恢复」。
3. 如果空配置启动后备份列表也是空的，说明 `backups\` 目录也被破坏了 —— 见 §4.4。

### 症状 2.2：启动后窗口是黑的 / 全空白 / 按钮点不动

**可能原因**：WebView2 运行时没装好（与症状 1.1 同因，但表现不同）。

**自助处置**：

1. 看任务栏右下角有没有 ASD 图标。**有**图标说明进程在跑，是 WebView2 没渲染。
2. 结束所有 ASD 进程 → 按 §1.1 装好 WebView2 → 重启应用。

### 症状 2.3：状态栏底部圆点一直是黄色「启动中」（超过 10 秒）

**可能原因**：

- AHK 子进程启动慢（旧机器常见）
- 防病毒软件拦了 `ahk_executor/AutoHotkey64.exe`（首次启动会被部分杀软当作可疑行为）

**自助处置**：

1. 等 30 秒（首次启动 + Windows Defender 扫描最慢）。
2. 打开 Windows Defender / 你装的杀软 → 「病毒和威胁防护」→「保护历史记录」→ 看有没有被拦截的 `AutoHotkey64.exe` → 「允许」。
3. 仍然黄 → 进「诊断信息」页（导航栏最下面） → 看「执行器状态」是否仍是「启动中」/「挂起」/「失败」。如果是「挂起 / 失败」 → 见症状 2.4。

### 症状 2.4：状态栏底部圆点变红「失败」（执行器异常）

**最可能原因**：AHK 子进程崩了或卡死。看门狗可能已尝试重启但**超过最大重启次数**，状态卡在「失败」。

**自助处置**：

1. 进「**诊断信息**」页（导航栏最下面，「调试监控」下方）：
   - 看「**执行器状态**」字段。
   - 看「**重启次数**」字段（如果有）。
   - 看「**日志目录**」字段下方的实际路径 → 打开文件资源管理器 → 找到当天日期的 `asd.<YYYY-MM-DD>.log` → 用记事本打开 → 拉到文件末尾 → 看最近 20 行 ERROR / WARN 信息。
2. 如果日志里有 `OutOfMemory` / `AccessViolation` / 具体 AHK 脚本错误：把出错信息记下来（截图最好）。
3. 点诊断页右下 **「重置看门狗」** 按钮 → 弹提示「看门狗已重置，正在重新拉起执行器」 → 等 5 秒，状态应回到「就绪」（绿）。
4. 重置后**仍然失败**：完全关闭应用（任务管理器杀光 ASD 进程）→ 重新启动。
5. 重启后还失败：**清掉全部备份之外的状态**：
   - 备份好当前能用的备份文件（如果备份列表能访问，复制 `%APPDATA%\com.asd.tauri\backups\` 到桌面）。
   - 关闭应用 → 把 `%APPDATA%\com.asd.tauri\config.json` 重命名为 `.bak`（保留）。
   - 重启应用 → 仪表盘为空 → 进「备份管理」→ 恢复一个已知的「好」备份。
6. 还失败 → 见 §6。

### 症状 2.5：应用能开，但所有页面白屏 / 某个具体功能没反应

**自助处置**：

- 点右上角 **「热重载」** → 重新从磁盘读配置、刷新 UI。
- 关掉应用 → 重启。
- 还不行 → 进「调试监控」页，看「实时日志」区有没有红色 ERROR 字样 → 点 **「清空日志」** 后 → 复现你刚才的操作 → 看新出现的错误内容。

## 3. 按键与热键问题

### 症状 3.1：按热键没反应

**可能原因**：

- 全局开关被关着（按 `Ctrl+1` 切换）
- 紧急停止后忘了重启
- 热键被另一个应用占用
- 该分组的触发热键被另一个分组占用（同热键只一个生效）
- 「长按模式」开关与「长按」型分组冲突
- 该分组处于「运行中」状态，但模式参数填错（如按键名拼错）

**自助处置**：

1. **看全局开关状态**：右上角「全局开关」按钮颜色（亮紫色 = 开，灰色 = 关），按 `Ctrl+1` 或点它切换。
2. **按紧急停止一次**（`F12`）→ 释放所有键 → 再按一次原热键试试。
3. **去仪表盘看分组状态**：卡片左侧绿条 = 运行中；卡片右下应显示「启动」按钮（不是「停止」）→ 说明分组根本没启动 → 点「启动」。
4. **检查热键是否冲突**：「全局设置」→ 「控制热键」区看你的紧急停止 / 全局开关 / 显示状态 / 长按开关 / 释放长按**是否与分组热键同名**（如分组用 `F1`，全局「显示状态」也用 `F1`）→ 改一个。
5. **检查热键是否被系统 / 其他软件占用**：临时关掉其他可能用热键的工具（OBS、ChatGPT 桌面版、Stream Deck 等）→ 再试。
6. **看执行器状态**：仪表盘底部圆点不是绿色 → 见 §2.4。
7. **手动按一次按键看反应**：进「按键测试」页 → 录制模式 → 点「开始录制」→ 按一下你想绑定的键 → 看下方事件区有没有出现键名。**没有**说明键盘事件根本到不了应用（被系统层拦截）。

### 症状 3.2：按热键有反应，但按出来的键不对 / 漏键

**可能原因**：

- 模式参数填错（如序列模式的延迟太小、按键名拼错）
- 应用配置与实际游戏窗口焦点冲突（有些游戏需要窗口在最前才接收 AutoHotkey 注入）
- 防病毒软件拦截了发送的按键事件

**自助处置**：

1. 「按键测试」→ 「验证」标签 → 选该分组 → 「开始验证」→ 按触发热键 → 「停止验证」→ 对比「验证事件」与分组配置里你填的按键序列 → 看哪一步漏了或多了。
2. 把序列里每步的延迟**加大一倍**试试（如 100 → 200 ms）→ 保存 → 再触发 → 看是否漏键改善。
3. 检查游戏窗口是否在最前、且不是以管理员身份启动（AutoHotkey 与游戏的权限不同可能导致发不出去；游戏以管理员启动 + 应用非管理员启动，会失败；解法：两个都用管理员或都不用）。
4. 看防病毒 / Windows Defender 拦截记录（参考症状 2.3 第 2 步）。

### 症状 3.3：按键「卡住」按不回来（最危险）

**症状**：按了一次热键后，某个键在系统里**一直处于按下状态**，松不开。

**自助处置**：

1. **第一选择**：按 **紧急停止**（默认 `F12`，无论当前焦点在哪） → 应该立刻释放所有按住的键。
2. 不行 → 进应用主窗口 → 按 **全局开关**（`Ctrl+1`）→ 切到关 → 再按一次切回开 → 看是否恢复。
3. 还不行 → 直接结束应用：任务管理器 → 找 `ASD.exe` 和 `asd_executor.exe` → 右键「结束任务」→ 按住的键应立刻释放。
4. 释放后再次复现 → 该分组的「按键时长」调小 / 「释放长按」热键（默认 `Ctrl+r`）按一次。
5. 反复卡住 → 「诊断信息」页 → 看日志里有没有 `SendInput` / `KeyDown` 相关错误 → 把日志截图保留 → 见 §6。

## 4. 配置与备份问题

### 4.1 关键文件位置（速查）

| 内容 | 路径 |
|---|---|
| 当前配置 | `%APPDATA%\com.asd.tauri\config.json` |
| 备份目录 | `%APPDATA%\com.asd.tauri\backups\` |
| 日志文件 | `%APPDATA%\com.asd.tauri\asd.<YYYY-MM-DD>.log`（最近 7 天，循环覆盖） |

> `%APPDATA%` 在文件资源管理器地址栏直接粘就能打开，等价于 `C:\Users\<你的用户名>\AppData\Roaming\`。如果地址栏粘了没反应，先在文件管理器顶上勾上「查看」→「显示」→「隐藏的项目」（`AppData` 默认隐藏）。

### 症状 4.2：仪表盘为空，但「备份管理」里有备份

**最可能原因**：配置加载失败，看应用是否在启动时**弹过窗**「配置文件未能读取……」。

**自助处置**：

1. 进「备份管理」→ 选最近一条「auto」后缀的备份（这是自动备份，每次保存配置时生成）→ 「恢复」。
2. 仍然空 → 选一条手动备份恢复。
3. 还不行 → 见 §2.1 第 2 步（手动改 `config.json.bak` 后启动）。

### 症状 4.3：误删了某个分组

**自助处置**：

1. 进「备份管理」→ 找最近一条备份（删除操作前自动生成的「auto」备份大概率还在）→「恢复」→ 该分组回来，但**当前所有配置也会被覆盖**。
2. 如果只想找回那一个分组：备份列表里点「导出」→ 编辑 JSON 文件 → 单独复制那一段 → 用「导入」功能追加回去（详见 user-guide §9）。

### 症状 4.4：备份目录空了 / 全是损坏的 .json

**最可能原因**：`%APPDATA%` 被清理工具（CCleaner、Disk Cleanup 等）一起删了，或者重装系统前没备份。

**自助处置**：

- **如果有网盘 / U 盘上之前的导出 JSON**：「仪表盘」→「导入」→ 选那个文件 → 分组回来（ID 可能冲突，按提示改）。
- **如果连导出都没有**：只能从「日志 + 手写 JSON」恢复 —— 这已经超出自助范围，建议见 §6。
- **预防**：今后定期用「仪表盘 → 导出全部」保存一份到非系统盘；备份目录里的文件不要批量删。

### 症状 4.5：导入 JSON 报错「ID 冲突」

**自助处置**：导入前用文本编辑器打开 JSON 文件，把里面的 `id` 字段全部改成不冲突的字符串，再导入。详见 user-guide §9.2。

## 5. 应用内可用的自助恢复入口（速查表）

| 你想做的事 | 在哪个页面 | 操作 |
|---|---|---|
| 看执行器（子进程）状态 | **诊断信息**（导航栏最下） | 看「执行器状态」字段 |
| 重置执行器（卡死 / 失败时用） | 诊断信息 | 点右下「重置看门狗」 |
| 看实时日志 | **调试监控** | 看「实时日志」区 |
| 清空日志 | 调试监控 | 点「清空日志」 |
| 切换自动滚动 | 调试监控 | 点「自动滚动」按钮（图 13 有提示） |
| 创建当前配置快照 | **备份管理** | 点「+ 创建备份」 |
| 恢复某次备份 | 备份管理 | 选中条目 → 点「恢复」→ 确认 |
| 删某次备份 | 备份管理 | 选中条目 → 点「删除」 |
| 测单个键的内部名 | **按键测试** → 录制模式 | 开始录制 → 按键 → 停止 |
| 验证分组实际发出的键 | 按键测试 → 验证模式 | 选分组 → 开始验证 → 触发 → 停止 |
| 一键释放所有按住的键 | **任意页面**右上 / `F12` | 「紧急停止」 |
| 一键暂停 / 恢复所有分组 | 任意页面右上 / `Ctrl+1` | 「全局开关」 |
| 不重启应用刷新 UI | 任意页面右上 | 「热重载」 |

> ⚠️ 历史版本的开发者文档（`docs/developer-guide.md`）里有一段「排障」直接让你 `invoke('get_executor_status')` / `invoke('reset_watchdog')` —— 那是**面向开发者**的内部 API 路径。**作为终端用户，你不需要也不应该去调它**。本表里的「诊断信息」页就是你应使用的等价 UI 入口。

## 6. 找不到答案怎么办

按上面 §1–§5 都试过仍然不行：

1. **收集证据**（缺一不可，否则没人能帮你看）：
   - 操作系统版本（`winver` 命令）
   - 是否装好 WebView2（控制面板 → 程序 → 搜「Microsoft Edge WebView2 Runtime」）
   - 应用版本：「诊断信息」页看「应用版本」字段
   - 最近 3 天日志：从 `%APPDATA%\com.asd.tauri\` 复制 `asd.<YYYY-MM-DD>.log` 三份到桌面
   - 复现步骤：「我在做 X 之后点 Y，应用表现 Z」
   - 截图：主窗口 + 「诊断信息」页 + 调试监控页（如有错误）
2. **保留原始配置**：在改任何东西之前，把 `%APPDATA%\com.asd.tauri\` 整个目录拷贝到桌面，命名 `com.asd.tauri-<日期>.bak`。
3. **到本仓库提 Issue**：附上以上材料。提 issue 时**不要只描述「不工作」**，要带具体复现路径与日志 / 截图。
