# 按键测试页面功能完善设计

日期: 2026-05-21

## 问题

| # | 问题 | 严重程度 |
|---|------|----------|
| 1 | 验证不能独立执行，只能验证正在运行的分组 | 严重 |
| 2 | 验证时需手动输入分组ID，无法从现有分组列表选择 | 中等 |
| 3 | 导出后无法导入分组，录制结果无法直接使用 | 严重 |
| 4 | 录制可视化不足，时间线只有圆点 | 轻微 |
| 5 | 验证流程不完整，需要手动触发分组执行 | 严重 |

## 设计

### 1. 验证流程重构：自动触发+验证

**新流程**: 下拉选择分组 → 点击"开始验证" → 自动触发分组执行 → 收集时序 → 自动停止 → 生成报告

**后端改动**:
- `WebView2Manager._BridgeStartValidation(groupId)` 增加自动触发分组执行
  - 启动 KeyValidator
  - 自动调用 `SkillManager.StartGroup(groupId)` 触发执行
  - 设置定时器，在分组执行一轮后自动停止验证
- 新增 `_BridgeGetGroupList()` 返回所有分组ID和名称的JSON
- 验证完成后自动调用 `KeyValidator.Stop()` 并返回报告

**前端改动**:
- 验证面板：移除手动"停止验证"的必要性，但保留按钮作为手动停止选项
- 验证启动后显示进度状态
- 自动接收验证报告并展示

### 2. 分组选择器

- 验证面板的 `<input>` 替换为 `<select>` 下拉框
- 新增 `_BridgeGetGroupList()` Bridge 方法
- 页面切换到验证面板时自动调用刷新分组列表
- 下拉框显示格式: `分组ID (分组名称)`

### 3. 导出→编辑器填充

- 导出录制配置后弹出对话框，让用户填写分组ID和名称
- 新增 `_BridgeImportRecording(groupId, name, mode, config)` Bridge 方法
  - 在 SkillManager 中创建新分组
  - 使用录制的按键和间隔配置
  - 保存到配置文件
- 导出后自动切换到分组编辑器页面，选中新建的分组

### 4. 录制可视化增强

**Canvas 时间线改进**:
- down/up 事件对显示为水平色块，长度代表持续时间
- 相邻事件之间显示间隔毫秒数
- 不同设备用不同颜色（键盘绿色，鼠标蓝色）

**实时统计面板**:
- 按键总数
- 平均间隔
- 总时长
- 设备分布（键盘/鼠标比例）

### 5. 验证报告增强

- 对比时间线：预期 vs 实际并排显示
- 偏差热力图：每个按键的偏差用颜色表示（绿/黄/红）
- 详细表格增加预期按键列
