## TD-045 批次 1–4（非文档类 140 项中收干 113 项）

### 关键决策：不用 `[lints] workspace = true`

- **per-tool 继承不存在**：`[lints.clippy] workspace = true` 在本仓库 cargo 上
  报 `error: invalid type: boolean true, expected a string or map`。只有
  `[lints] workspace = true` 这一种写法，而它无法再逐条覆盖。
- 故改为 `src-tauri/Cargo.toml` 写**显式清单**：`pedantic = { level = "warn", priority = -1 }`
  + 未处理的 lint 逐条 `allow`，每批删一行 allow 翻一个 lint。
- **防复发不需要新脚本**：既有闸门 G2b（`cargo clippy --workspace --all-targets
  -- -D warnings`）天然守住 —— 不存在「守护与被测代码一起被改坏」的问题。
- 终态（全部收干后）才换成 `[lints] workspace = true`，已在注释里写明。

### ⚠️⚠️ 计数口径订正（本轮最有价值的发现）

`cargo clippy --all-targets` 会把**同一条告警在 lib / test 两个 target 各报一遍**。
台账 TD-045 原记「618 项 / 文档类 425 / 非文档类 193」是**未去重**的原始计数。
按 `(lint, 文件, 行, 列)` 去重后真实为 **约 430 / 290 / 140**。

**量 clippy 告警数的正确姿势**：`--message-format=json` 输出到文件（stdout，不是 stderr！），
解析 `message.code.code`，按 (code, file, line_start, column_start) 去重。
重复倍数不是固定的 2（实测 140 vs 193，约 1.38×），因为部分 lint 只在一个 target 触发。
这与 TD-025「基线不可复现」是同一类病：测量口径不同 → 数字对不上。

**批次 3 手修里唯一有实质价值的一处**：`config_compat_tests.rs` 4 处 `other =>`
改成 `other @ GroupItem::X { .. }`。`GroupItem` 只有 Periodic/Sequence 两个变体，
通配臂等价于「另一个变体」；写成显式后**将来新增变体会变成编译错误**，
而不是悄悄落到 panic 分支里被误判为「类型不符」。

**批次 4 逐个论证**：
- `backoff_duration - elapsed` → `checked_sub` + `if let Some(remaining)`。
  原写法靠上一行 `elapsed < backoff_duration` 保证不下溢，是隐式前提；改后语义一致、panic 路径消失。
  ⚠️ clippy 自己建议的 `.checked_sub(..).unwrap()` 是**同义反复**（一样 panic），别照抄。
- 测试里「N 秒前的 Instant」抽 `instant_ago(secs)` helper（watchdog.rs 2 处 + wd_it 1 处内联）
- `&mut x` → `std::ptr::addr_of_mut!(x)`；`from_ref(&info) as *const _` → `.cast()`
- `forward_to_outbound` 去掉无 await 的 `async` 并同步删两个调用点的 `.await`

**阳性对照**：每批各注入一条违规，G2b 均报 error 并指名 lint。
注入点统一用 `src-tauri/src/lib.rs` 末尾追加 `pub fn __td045_probe*`（用完 `cp` 还原）。
