# AHK 语言 / 运行时的坑 与 AHK 测试的坑

> 从 `MEMORY.md` 拆出以控制注入体积。改动此文件时同步检查 `MEMORY.md` 指针是否仍准确。

## AHK 语言与运行时的坑

- 箭头函数 `=>` **只支持表达式体**；类**静态方法只读** → 用注入字段（如 `_sendHook`）。
- v2 保留字不能作变量名（`log`/`in`/`out`/`case`…）。
- ⚠️ **标识符大小写不敏感** → 全局常量 `SAMPLES` 与局部 `samples` 是同一个变量；
  脚本级变量**不会**被箭头函数闭包捕获（assume-local）→ 包进 `Main()` 或 `global`。
  函数名与调用方局部变量同名时会解析成未赋值的局部变量，报错行指向**调用方**（极难定位）。
  常量名必须带前缀（如 `BATCH_CALLS`），自写工具函数带 `_` 前缀。
- ⚠️ `if true` **实测不生效**，要用 `if 1`。
- ⚠️ **源码里「一个反斜杠」写作 `"\"`**（双引号串中 `\\` 才表示一个反斜杠）。Python 写替换脚本
  极易因 `repr` 转义数错一倍 → 匹配失败先 hexdump 逐字节对比（「变异未生效」≠「变异被捕获」）。
  含引号/反斜杠的测试数据一律用 `Chr(34)`/`Chr(92)`。
- ⚠️ **不接受单行花括号块体**：`F(x) { return x*2 }` 报 `Unexpected {`，必须换行写。
- ⚠️ `result .= s` **不是 O(n²)**（4.10× 字符 → 4.12× 耗时，严格线性）。换 Buffer+`StrPut` **慢 46%**、
  数组聚合**慢 13%**。JSON 序列化 ≈ **0.24 µs/字符**的解释器常数 → **别优化累加方式**，
  出路只有「少序列化」（缓存/增量）。
- v2.0.26：`catch as e` 才对；**`Array` 没有 `Sort()`**；`Hotkey()`/`OnError()` 回调必须传
  **函数对象**（`((*) => 0)`）；`OnError` 多回调**全部执行**且 `-1` 移除不掉；
  `StrPut(s, 65001)` 非法，要写 `"UTF-8"`。
- **递归上限 ~1200–1500 层且 `try/catch` 捕获不到**（直接 ExitApp）→ 深递归必须改迭代。
- **循环引用 100% 泄漏**（纯引用计数、无环检测）：5 万个带环 Map 常驻 +22.9MB。
- 文件 API **无 MAX_PATH 限制**（30 038 字符正常，无需 `\\?\`）。
- **CP936/ANSI 码页往返会静默丢字符**（长度不变、内容变 `?`）→ IPC 必须锁死 UTF-8。
- ⚠️ **`#MaxThreads` 不能当背压**：30 个并发定时器在默认 10 下全部执行。
- 进程启动**必须先标定基线**：本机 `hostname.exe` 144.9ms（Defender），AHK 空脚本 163.5ms
  → 引擎自身仅 ≈19ms。**绝对值不可跨机比**。
- **热键注册边际成本平坦 38~55µs/个**（108 个共 4.48ms）→ `Manifest` 全量扫描的 O(n²)
  只是最坏界，**n≤108 实测不出**；**源码复杂度结论必须拿实测兜底**。
- 热键端到端时延 p50 **0.64~0.86ms**，不是瓶颈。

## AHK 测试的坑

- ⚠️ **时延类断言统计口径**：`_Pct(arr,0.95)` 索引 = `Ceil(n*0.95)`，**n=7 时断言的是最大值**。
  时延断言要 **≥40 样本**再算 P95；**判「是否漂移」用中位数**。**不要用 Map 收集中间结果**（同名键互覆盖）。
- ⚠️ **回归用例必须选「判别性取值」**：用 33.333/99.999 断言浮点不拆桶是**假阴性**
  （`33.333*1000` 双精度下恰好 = 33333.0）。要挑乘倍数后**非整数**的值：
  **16.001 → 16001.000000000002**、**1/7 → 142.857…**。
- ⚠️ **依赖运行时量级的行为类用例是弱守卫**，必须配确定性单元用例。
  （端到端「1:3 不拆桶」浮点拆桶率 48%~85% ≈ 20% 假阴性。）
- ⚠️ **宿主抖动无法从代码侧消除**（离群点幅度 ~15ms 远大于 1ms 阈值）
  → P95 实际只容忍 `floor(0.05n)` 个离群点，**n=54 也只容忍 2 个**。
  保持时长断言一律用 **中位数 ≤1ms 判漂移 + P95 ≤20ms（一个网格）兜底**。
- ⚠️ **「脏环境假阳性」**：断言路径与组件实际写入路径不一致时，只要该路径已存在就一直绿。
  **断言取组件自己的值**（`DebugLogger.logFile`）。
- `AutoHotUnitSuite` **下划线开头方法不收集为用例**。对 **Object 形态**（`{type:"ERROR"}`）
  **不能用 `[]` 取值**，须 `.prop` 或先判 `e is Map`。
- 隔离跑单个套件：复制 `run_all_tests.ahk` → 只注册目标套件 + 换日志名，跑完删掉。
- ⚠️ **汇总不进 stdout**（GUI 子系统）→ `>file` 恒 0 字节。结果写 **`tests/test_results.log`**，判成败读它。
- 注册新套件须在 `run_all_tests.ahk` 末尾 `RegisterSuite(...)` 块**最后一项后加逗号**；
  忘了 = 静默零覆盖，跑完 `grep <用例名>` 确认。全量约 27 秒、664 用例。

### 宿主时延断言：不要在共享 runner 上做硬判（`ASD_HOST_TIMING`）

- ⚠️ **绝对墙钟时延断言在共享 CI runner 上不可判定**（不是阈值没调好）。定刻走 QPC 忙等，
  CPU 争用下不是「变慢」而是**量级崩塌且存在悬崖**：12 线程机器，空载 0.005/15.015 →
  11 进程 0.005/15.015 → **14 进程 19.22/28.45** → 24 进程 ~111/~745。
  CI（2 vCPU 共享）正落在 11~14 之间 → **中位数也守不住，放宽 P95 无用**。
- 决定性证据：注入「定刻退化成网格 `Sleep`」后 P95 = **31.76ms**，与 CI 失败值 **31.86ms** 几乎相同
  → **共享 runner 上「实现退化」与「宿主忙」数值无法区分**。
- ⚠️ 别用「会让出 CPU 的探针」给忙等定刻做归一化（`Sleep 1` 超调地板在 24 burner 下只涨 0.44ms，
  而实际超额 100~700ms，完全不相关）。
- **现行处置**：`SenderPreciseTimingTests._HostTiming()` 门控 7 条绝对时延断言，
  `ASD_HOST_TIMING=0` 关闭（缺省执行）。CI G3b 设 0，本机四闸门不设 → 照跑（真正守护点）。
  CI 校验「跳过数 ≥1」防门控静默失效。
- 框架：`AutoHotUnit.ahk` 有 `AhuSkip extends Error` + `assert.skip(reason)`。
  ⚠️ `RunSuites` 里 `catch AhuSkip` 必须排在 `catch Error` **之前**（继承，反了会被吞）。
  ⚠️ `SilentReporter` 在 **`tests/suites/core_suites.ahk`**（不在 AutoHotUnit.ahk）；
  汇总新增的「跳过」行必须排在「失败」**之后**，否则 CI 的 `总计/通过/失败` 正则被打乱。
- ⚠️ 变异测试纪律：改实现前先 `cp` 备份，还原后校验「文件中不再含 MUTATION 标记」。
  ⚠️ **Sender 走 `SleepUntilUs`（µs 口径）不是 `SleepUntil`** —— 只变异 ms 版只能红 1 条。


## AHK 排查手法（2026-09-16 实证好用）

- **异常位置拿不到时**：临时给 catch 里的 `ErrorSystem.LogError(...)` 补上
  `e.File ":" e.Line " what=" e.What " stack=" e.Stack`，跑一次，读日志，然后 `git checkout` 还原。
  就这样定位到「`_DebugLog` 未定义」—— 原始信息「This local variable has not been
  assigned a value」完全没指向真因。
- **隐式依赖**：全局函数（如 `_DebugLog`）定义在 A 模块、被 B 模块调用却没 include A，
  只要 main 同时 include 两者就不会暴露。查法：`grep -rn "^函数名" ` 看定义点，
  再对比调用文件的 `#Include` 列表。
- **AHK v2 里非空字符串是真值**：`return "error"` 配 `if fn()` 会把失败当成功。
  跨语言边界的返回值不要用字符串表示失败。

## 写 AHK 探针的两个硬要求

1. 输出**写文件**（`A_Temp "\x.txt"`），不要写 `"*"`（stdout）—— 有缓冲，脚本不退出就不 flush，
   会把「卡住」误判成「没输出」。
2. 必须加 `#ErrorStdOut "UTF-8"` —— 否则 `#Include` 路径写错时 AHK 弹**阻塞式错误对话框**，
   同样表现为「卡死」。从 `tests/` 引上级目录要写 `..\infrastructure\...`。

## ⚠️ `FileDelete` 对不存在的文件会**终止当前线程**（AHK v2.0.26 实测，2026-09-17）

三连对照实验：

| 场景 | 结果 |
|---|---|
| 无 `FileDelete` | 正常走到底 |
| `FileDelete` 目标**存在** | 正常返回，继续往下 |
| `FileDelete` 目标**不存在** | **后面一行都不执行**，退出码仍是 **0**，且**连 `OnError` 都不会被调用** |

第三行是致命组合：配 `OnError((e, m) => (..., true))` 这种「已处理」吞错写法，脚本会
**静默空转而退出 0** —— 任何按退出码判断的 runner 都会显示通过。实测后果：
`tests/test_webview2_bridge.ahk` 的 38 条断言**从未执行过一次**（TD-048）。

**而且换成 `ExitApp(99)` 的 OnError 也照样退出 0**（插桩实证：`FileDelete` 之后的标记点
没有输出，退出码也不是 99）。所以**不能指望 OnError 兜住它**。

对策：
1. **删除前先判 `FileExist`** —— 唯一可靠的办法。
2. 依赖退出码的门禁不能只看退出码，必须校验「本次运行留下了新鲜产物」
   （`scripts/run-standalone-ahk-tests.sh` 就是这么改的）。
