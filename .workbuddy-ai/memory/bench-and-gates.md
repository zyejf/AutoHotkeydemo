# 性能基准与门禁

## AHK 重构基准（`tools/ahk-bench/`，结论落点 `docs/refactor/`）

生产代码**零改动**：脚本内置旧实现（原样复刻）+ 新实现，同进程同数据对比 + 等价性校验。
`bash tools/ahk-bench/run.sh <id>`；`cycle_leak_all.sh`（内存类须每用例独立进程）；
`python tools/ahk-bench/report.py [--prev <dir>...]`。

**内存类两条硬纪律**：① 必须带**阳性对照**；② 必须**每用例独立进程**（同进程基线漂移
3216→4696KB，残留量会算出负值）。

**统计口径**：① 用 p50 判不用 max；② P95 需足量样本（n=54 只容忍 2 个离群点），判漂移用中位数；
③ 结论必须**跨轮可复现**；④ CPU 类必须给多轮区间并**检查是否重叠**，重叠即未测出差异。

**结论（三轮）**：json_escape **19~41×**；tick 遍历合并 **1.80~1.96×**；键名校验 **1.03×（无收益，不改）**；
定时器忙等**只改善尾部稳定性**（new 0.17~0.23ms vs old 1.05~4.92ms）；对象互指**确认泄漏**
19,956KB/5万（408.7B每组）；**自引用闭包不泄漏**（推翻代码走查推断）。

**启动基线**：`empty` p50 164.33ms；`hostname.exe` 144.85ms → 引擎自身约 19ms。
**`#Include` 边际 673µs/文件**（解析仅 1.44µs/行）→ 启动优化唯一确定杠杆是**减少文件数**。

坑：`case` 是 AHK v2 保留字；反斜杠路径上 `rm`/`[ -e ]` 不可靠 → 先 `cygpath -u`；
`FileAppend` 默认系统 ANSI → 必须 `FileAppend(..., "UTF-8")`。

## 生产基准门禁（T11，gate.py）：共享 runner 上**绝对毫秒不可用**

**硬事实**：同一份代码在 GitHub 托管 runner 跨 run 的**绝对**耗时散布达 **3.7~3.9 倍**
（0.52× / 0.79× / 0.92× / 1.07× / 1.87~2.09×，同一 run 内 5 个 metric **同步**移动）。
历史文档的「runner 池 ±10~17%」是**严重低估**，勿引用。

- 绝对值基线两头不讨好：慢机器上无变化也 FAIL；快机器上真实 2× 回退读成 1.04× 而 PASS（漏报更危险）。
- 故 `prod_escape`/`prod_tick` 的 p50 **都是归一化值** = 被测耗时 ÷ 同进程紧邻测得的参考负载耗时
  （纯 AHK Array 算术循环）；原始毫秒留 `raw_ms=` 仅供排障。`gate.py` **不认 info 行**。
- ⚠️ **参考负载对 CPU 争用「过度校正」但方向安全**：争用只会**压低**读数（不误报、灵敏度下降）
  → **别据此收紧 K**。
- **K 按信噪比分别定**：`prod_escape` **1.5 / warn 1.25**（T1 信号 41~49×）；
  `prod_tick` **1.4 / warn 1.2**（T6 信号仅 ~1.7×）。
- **定性手法**：多 metric 倍率**挤在同一窄带**＝整机速度因子；某条路径退化则倍率**严重分化**
  （T1 回退时 plain_* 涨 40× 而 ctrl 兜底档 0.99× 不动）。
