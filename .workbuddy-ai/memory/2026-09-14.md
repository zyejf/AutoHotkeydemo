### 1. 排查 `Test_ExecutePeriodic_EndToEndLatencyP95Within20ms` 偶发失败

- 现象：完整套件里偶发失败，观测值 **77.70 ms** 与 **28.37 ms**（两次不同），
  单独跑 `SenderPreciseTimingTests` 却 9/9 全绿。
- 排查手法：复制 `run_all_tests.ahk` → 只注册 `SenderPreciseTimingTests` + 换日志文件名，
  跑完删掉。**这是判断「回归 vs 跨测试干扰」最快的一招**。
- 根因：**不是回归**。kpd 默认 15ms、预算 20ms，**可用余量只有 5ms**，
  宿主（OS 抢占）一次 >5ms 延迟就让样本超标。打点后干净环境下 42 个样本全部落在
  15.01~15.02 ms（`min 15.009 / max 15.024`），零离群。

### 2. 真正的缺陷：测试统计口径错了

`_Pct(arr, 0.95)` 索引 = `Ceil(n*0.95)`，**n=7 时索引=7 → 断言的是最大值（P100）**，
宿主抖动一次就红。修正：

| 断言性质 | 统计量 | 样本量 |
|---|---|---|
| 端到端时延 P95 ≤ 20ms | P95 | 42 个（窗口 700ms → 4200ms） |
| 保持时长 == kpd | P95 | 20+ |
| **步进是否漂移** | **中位数** | 20+（漂移是系统性偏移，中位数即可检出，不被个别离群污染） |

另修 hybrid 用例：**旧写法把 `holds`/`steps` 存进 Map，同名键互相覆盖，最终只剩 1 个样本**
（等于单样本断言）。改为数组 + 中位数/P95。

### 3. 新测出的代价：精确定刻会连续占用 AHK 主线程

挂 5ms 探针定时器统计唤醒间隔（interval=100/kpd=15，3s）：

| 指标 | 实测 |
|---|---|
| 探针间隔 P50（定时器网格本身） | 16.08 ms |
| 探针间隔 P95 / 最大 | 43.98 / 47.47 ms |
| **扣除网格后最长连续占用** | **31.39 ms** |
| 占用占空比 | **29.2 %** |

原因：`SleepUntil` 中段用 `DllCall("kernel32\Sleep", 0)` 让出，**不会放行其它 AHK 定时器**
（AHK 定时器靠消息循环派发，回调内不泵消息）。后果：IPC 命令/热键最多被推迟 ~31 ms。
旧实现（`SetTimer(-kpd)` 异步释放）完全不阻塞 —— **这是用单线程忙等换亚毫秒精度的固有代价**。
暂未改（改「多段提前唤醒」可压到 ~16ms，但要多承担一次定时器抖动风险，而时延是首要需求）。

### 4. 隔离探针脚本的坑（下次直接复用）

- `log` 是 AHK v2 内置函数 **`Log()`**，不能作变量名（报 "This Func cannot be used as an output variable"）。
- 脚本级（auto-execute）变量**不会**被箭头函数闭包捕获（函数 assume-local）→ 报
  "This local variable has not been assigned a value"。**把探针主体包进 `Main()`** 即可。
- `while i <= n { ... }` 单行块体非法，必须多行。
- 单独 include `sender.ahk` 时 `Joystick` 未定义 → `_StopGroup` 会抛
  "Item has no value"（line 211）。探针里别调 `ToggleGroup`，或把 `FileAppend` 写在它之前。
- 跑 AHK 探针用 Bash 直接调 `AutoHotkey64.exe`（GUI 程序，PowerShell 不等待）。
