### 关键根因（本次已确证，非推测）

1. **E2E 8/9 失败的根因 = `"Origin header is not a valid URL"`**
   —— 用诊断 spec 捕获**原始 reject 值**得到：`ctor='String'`, `keys=[]`, `json='"Origin header is not a valid URL"'`。
   这是 **WebView2/msedgedriver WebDriver 协议层**拒绝 Tauri 自定义协议 origin，
   **不是 Rust AppError**（否则会有 `{kind,message}`）。对 `get_config` 同样复现 → 与命令无关，是桥接层通病。
   `tauri.js` 文件头注释**已记载**此问题并声称改用 `/execute/sync` 规避，但**失败依旧** →
   说明规避未生效或 `/execute/sync` 同样触发 Origin 校验。轮询 `try-catch` 只是把失败**延迟 15 秒**，不能解决。
   **生产环境不受影响**（Tauri 走自己的 IPC，不经 WebDriver）。

2. **clippy 的 ICE 是 `target/debug/.fingerprint` + `incremental` 缓存损坏**，非代码问题。
   `cargo clean -p asd-tauri` + 删 `target/debug/incremental` 后 → `Finished`，0 代码告警。
   残留 1 条 `error copying object file ... os error 5` 是**增量缓存写入权限问题**（杀毒/占用），非代码告警。

3. **测试数登记漂移**：`asd-tauri` 实际 **243** vs 登记 231（+12）。
