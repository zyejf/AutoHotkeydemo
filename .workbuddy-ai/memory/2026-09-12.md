### A-1 详情（唯一 soundness 相关项，值得记住）

**根因**：`windows 0.62.2` 的 `HANDLE(pub *mut c_void)` **既非 `Send` 也非 `Sync`**
（与 std 的 `OwnedHandle` 不同，std 为其手写了 `unsafe impl`）；
`std::process::Child` 是 `Send + !Sync`。二者直接作为 `ProcessWatchdog` 字段
把 `!Sync` 传染给该类型，原作者因此手写 `unsafe impl` —— 代价是编译器
**从此不再校验任何字段**，新增未保护字段即静默 UB。

**修复方案**：拆成两个可独立审计的命题，收敛到最小泛型边界

```
HANDLE (:: !Send + !Sync)
  └─ RawHandle        : unsafe impl Send           ← 命题 1（句柄是内核对象 ID，可移动）
       └─ SendSyncCell : T: Send ⇒ Send + Sync     ← 命题 2（不暴露 &T，靠外层 Mutex 串行化）
            ├─ JobObjectGuard  : 自动推导
            └─ ProcessWatchdog : 自动推导 Send + Sync + 'static  ← 原 2 处 unsafe 已消除
```

关键设计点：
- `SendSyncCell::with / with_mut` 要求返回值 `R: Send`，从**类型层面阻断借用逃逸**
  （把原作者在 `state()` 上手工维持的不变量升级为编译期检查）
- 手写 `unsafe impl` 由 4 处收敛为 3 处，`ProcessWatchdog` 的 2 处彻底消除
- 新增 `!Sync` 字段：由「静默通过」变为「编译期 E0277」

**两组故障注入均已实测验证**：
1. 注入 `Cell<u32>` 字段 → `E0277: Cell<u32> cannot be shared between threads safely`
2. 加回手写 `unsafe impl Send` → 白名单测试精确报出违规行

新增 3 个回归防线：`test_send_sync_cell_wrapping_chain_is_sound`、
`test_process_watchdog_send_sync_is_derived_not_declared`、
`test_no_handwritten_unsafe_send_sync_for_watchdog_types`
