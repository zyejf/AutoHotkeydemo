## 阶段 2 第一项：TD-006 覆盖率棘轮门禁（已完成）

基线 **整体 81.64%**（命中 5206 / 总行 6377，15 个文件），逐文件数字在
`asd-tauri/docs/test-map.md`「覆盖率」节（该表是 `coverage-baseline.json` 的可读镜像）。

设计要点（`scripts/check-coverage.py`，CI 的 **G3f**）：
- **棘轮不设绝对值**。凭空定「≥80%」只有两种下场：一上线就红（逼出无断言的刷数
  测试），或低到形同虚设 —— 两种都比没有门禁更糟，因为它们**污染指标本身的可信度**。
- **双阈值**：整体 −0.5pp 防「总体稀释」，单文件 −2.0pp 防「丢车保帅」。
  阳性对照 2 证明了双阈值不是过度设计：小文件 100%→25% 时整体只跌 0.47pp，
  **只设整体阈值会完全漏掉**。
- **lcov 的 SF 是绝对路径**（本机 `D:\...`、CI `/home/runner/...`），
  必须归一化成 `<crate>/src/...` 才能跨平台比基线。
- 新文件只登记不判；基线里消失的文件（被删/改名）会被报出来。
- CI 的 coverage job 由 `continue-on-error` + 仅 push，改为**始终阻断**；
  `cargo install cargo-llvm-cov` 换成 `taiki-e/install-action`（预编译），
  否则「红灯与代码无关」会让门禁迅速被全员忽略。

## TD-019 冗余成员 Cargo.lock（已完成，commit `732c110`）

删除 `asd-tauri/src-tauri/Cargo.lock` + 新增 **C5 守卫**。

## ⚠️ 工具教训（本会话踩了两次）

1. **`io.open(p,'w', newline='\\n')` 会先截断文件再校验 newline** → 脚本报
   `ValueError: illegal newline value` 时文件已被清空（本会话把 check-tech-debt.py
   清成 0 字节，靠 `git checkout --` 恢复）。heredoc 里 `\\n` 会被原样传成
   `\\n`；要用 `'\n'`。**批量改文件一律写成 .py 脚本文件用 Write 落盘再执行**，
   别用 heredoc。
2. 批量 Edit 同一文件容易静默丢失 → 改用「Python 脚本 + 每个锚点 `assert count==1`」
   一次改完，锚点不唯一时**在写盘前**就失败，不会污染文件。
