## 阶段 2 第一项：TD-006 覆盖率棘轮门禁（已完成）

基线 **整体 81.64%**（命中 5206 / 总行 6377，15 个文件），逐文件数字在
`asd-tauri/docs/test-map.md`「覆盖率」节（该表是 `coverage-baseline.json` 的可读镜像）。

设计要点（`scripts/check-coverage.py`，CI 的 **G3f**）：
- **棘轮不设绝对值**。凭空定「≥80%」只有两种下场：一上线就红（逼出无断言的刷数
  测试），或低到形同虚设 —— 两种都比没有门禁更糟，因为它们**污染指标本身的可信度**。
- **双阈值**：整体 −0.5pp 防「总体稀释」，单文件 −2.0pp 防「丢车保帅」。
  阳性对照 2 证明了双阈值不是过度设计：小文件 100%→25% 时整体只跌 0.47pp，
  **只设整体阈值会完全漏掉**。
- **lcov 的 SF 是绝对路径**（本机 `D:\...`、CI `/home/runner/...`），
  必须归一化成 `<crate>/src/...` 才能跨平台比基线。
- 新文件只登记不判；基线里消失的文件（被删/改名）会被报出来。
- CI 的 coverage job 由 `continue-on-error` + 仅 push，改为**始终阻断**；
  `cargo install cargo-llvm-cov` 换成 `taiki-e/install-action`（预编译），
  否则「红灯与代码无关」会让门禁迅速被全员忽略。

## TD-019 冗余成员 Cargo.lock（已完成，commit `732c110`）

## ⚠️ 工具教训（本会话踩了两次）

1. **`io.open(p,'w', newline='\\n')` 会先截断文件再校验 newline** → 脚本报
   `ValueError: illegal newline value` 时文件已被清空（本会话把 check-tech-debt.py
   清成 0 字节，靠 `git checkout --` 恢复）。heredoc 里 `\\n` 会被原样传成
   `\\n`；要用 `'\n'`。**批量改文件一律写成 .py 脚本文件用 Write 落盘再执行**，
   别用 heredoc。
2. 批量 Edit 同一文件容易静默丢失 → 改用「Python 脚本 + 每个锚点 `assert count==1`」
   一次改完，锚点不唯一时**在写盘前**就失败，不会污染文件。

## TD-010 处置 vendored AHK 引擎（`AutoHotkey-2.0.26/`）

**摸底推翻了登记时的判断**：真正的成本不是体积，是**纯度**。

### C6 的两个口径（都是实测踩出来的）

1. **路径**用 git 自己的口径：`ls-files -s`（已跟踪）+ `ls-files --others --exclude-standard`
   （未跟踪但未被 ignore）。被 ignore 的本机产物（`AutoHotkey.exe`、`*.log`）**不管** ——
   它们只在本地存在，管了就「本地恒红、CI 恒绿」，那种门禁会被人学会无视。
   （第一版裸扫文件系统，多报了 18 个 ignored 产物。）
2. **内容**用**工作区**哈希 `git hash-object --stdin-paths`，**不是索引**。
   第一版用 `ls-files -s` 的索引 sha，阳性对照「改了引擎源码但还没 `git add`」是**全绿的** ——
   而那正是要防的，等进了索引错误已经提交出去了。
   `git hash-object` 与 .gitattributes 同一套归一化口径，实测与上游 sha 一致。

**阳性对照 3 组**：改工作区文件（不 add）→ 被改 1；移出已跟踪文件 → 被删 1；
基线加不存在的文件 → 缺失 1；还原后全部回 0。

**基线取自上游而非本地快照**：取本地快照的话，一旦本地已被污染，污染就会被固化进
基线、从此永远通过。校验的是「本地 == 官方」，不是「本地 == 本地上一次的样子」。

### 为什么 traits.rs 恒 0%（不是「忘了写测试」）

**trait 的默认方法体只为「实例化的具体类型」生成代码**。该文件定义的三个 trait

cargo-llvm-cov 测的是**测试二进制**，内联测试一并进分母。实测测试代码占比：
`time_format.rs` 83.9% / `traits.rs` 77.9% / `validator.rs` 60.9% / `config.rs` 58.0% /

### 漂移检测器的误报修正（check-coverage.py）

补测试后 traits.rs 统计行数 15 → 146（+873%），漂移检测 FAIL —— 但那是**真实新增**不是换尺子。
