## 阶段 2 第一项：TD-006 覆盖率棘轮门禁（已完成）

基线 **整体 81.64%**（命中 5206 / 总行 6377，15 个文件），逐文件数字在
`asd-tauri/docs/test-map.md`「覆盖率」节（该表是 `coverage-baseline.json` 的可读镜像）。

设计要点（`scripts/check-coverage.py`，CI 的 **G3f**）：
- **棘轮不设绝对值**。凭空定「≥80%」只有两种下场：一上线就红（逼出无断言的刷数
  测试），或低到形同虚设 —— 两种都比没有门禁更糟，因为它们**污染指标本身的可信度**。
- **双阈值**：整体 −0.5pp 防「总体稀释」，单文件 −2.0pp 防「丢车保帅」。
  阳性对照 2 证明了双阈值不是过度设计：小文件 100%→25% 时整体只跌 0.47pp，
  **只设整体阈值会完全漏掉**。
- **lcov 的 SF 是绝对路径**（本机 `D:\...`、CI `/home/runner/...`），
  必须归一化成 `<crate>/src/...` 才能跨平台比基线。
- 新文件只登记不判；基线里消失的文件（被删/改名）会被报出来。
- CI 的 coverage job 由 `continue-on-error` + 仅 push，改为**始终阻断**；
  `cargo install cargo-llvm-cov` 换成 `taiki-e/install-action`（预编译），
  否则「红灯与代码无关」会让门禁迅速被全员忽略。

## TD-019 冗余成员 Cargo.lock（已完成，commit `732c110`）

## ⚠️ 工具教训（本会话踩了两次）

1. **`io.open(p,'w', newline='\\n')` 会先截断文件再校验 newline** → 脚本报
   `ValueError: illegal newline value` 时文件已被清空（本会话把 check-tech-debt.py
   清成 0 字节，靠 `git checkout --` 恢复）。heredoc 里 `\\n` 会被原样传成
   `\\n`；要用 `'\n'`。**批量改文件一律写成 .py 脚本文件用 Write 落盘再执行**，
   别用 heredoc。
2. 批量 Edit 同一文件容易静默丢失 → 改用「Python 脚本 + 每个锚点 `assert count==1`」
   一次改完，锚点不唯一时**在写盘前**就失败，不会污染文件。

## TD-010 处置 vendored AHK 引擎（`AutoHotkey-2.0.26/`）

**摸底推翻了登记时的判断**：真正的成本不是体积，是**纯度**。

- **CI 对该目录零依赖**（CI 用 `ahk_executor/AutoHotkey64.exe`）。
- 体积不是主要矛盾：7.9M 相对 `.git` 100M 只占约 8%，且是一次性成本。

**处置**：移出 40 个文件（221→181，备份在 TEMP，可从 `461f6f5` 取回）+ 新增 **C6 守卫**。

**submodule 方案评估后不采纳**（可行但不划算）：研究报告有 **60+ 处行级引用**
（`script.cpp:9840`、`hotkey.cpp:202`…，涉及 20 个文件），submodule 会让普通 clone
得到空目录 → 引用悬空，把「随时可查」变成「需要网络 + 额外步骤」。

### C6 的两个口径（都是实测踩出来的）

1. **路径**用 git 自己的口径：`ls-files -s`（已跟踪）+ `ls-files --others --exclude-standard`
   （未跟踪但未被 ignore）。被 ignore 的本机产物（`AutoHotkey.exe`、`*.log`）**不管** ——
   它们只在本地存在，管了就「本地恒红、CI 恒绿」，那种门禁会被人学会无视。
   （第一版裸扫文件系统，多报了 18 个 ignored 产物。）
2. **内容**用**工作区**哈希 `git hash-object --stdin-paths`，**不是索引**。
   第一版用 `ls-files -s` 的索引 sha，阳性对照「改了引擎源码但还没 `git add`」是**全绿的** ——
   而那正是要防的，等进了索引错误已经提交出去了。
   `git hash-object` 与 .gitattributes 同一套归一化口径，实测与上游 sha 一致。

**阳性对照 3 组**：改工作区文件（不 add）→ 被改 1；移出已跟踪文件 → 被删 1；
基线加不存在的文件 → 缺失 1；还原后全部回 0。

**基线取自上游而非本地快照**：取本地快照的话，一旦本地已被污染，污染就会被固化进
基线、从此永远通过。校验的是「本地 == 官方」，不是「本地 == 本地上一次的样子」。

产物：`scripts/vendor-baseline-ahk-2.0.26.txt`（181 条 + 头部注释说明来源与刷新方法）。
文档：register / developer-guide / graph-driven-workflow / AGENTS.md 四处同步。
**P1 至此全部完成**（P0 8 + P1 8 + P2 8 = 24 项）。

### 工具/方法可复用点

- **验证 vendored 副本是否纯净**：`gh api repos/<o>/<r>/git/trees/<tree>?recursive=1`
  拿上游每个 blob 的 sha，与本地 `git ls-files -s` 比对。git blob sha 是通用的，

## TD-009 更正 crate 依赖允许矩阵 + 新增豁免卫生检查

**结论：那 3 条「违规」不是豁免，是漏填。**

`ALLOWED_CRATE_DEPS["asd-test-harness"]` 一直是空集，而它的 3 个生产依赖
（asd-domain / asd-ipc-protocol / asd-application）是**真实且承重**的 ——
`lib.rs` `pub use` 了 domain 的 trait 与类型，并用到 `AppState`。
测试辅助 crate 位于最深的 tests 层，**依赖被测代码是正确方向**；真风险是反向，
而反向已被挡住（三个生产 crate 的允许集里都没有 harness）。

→ 补入允许矩阵，违规 **3 → 0**；而不是给 3 条假豁免编理由。

⚠️ **查出一个必须保持的现状**：`asd-application` 的 `[dev-dependencies]` 里有
`asd-test-harness`，与 `asd-test-harness ──→ asd-application` 生产边构成
**dev 依赖环**。cargo 允许 dev-dep 环，环检测按既定策略只用生产边 → `rust_crate_cycles` 仍 0。
**但这条边必须保持 dev-only** —— 挪进 `[dependencies]` 就是真生产环。已写进 AGENTS.md。

**防复发（比填 3 个字符串有价值得多）**：`check-graph-baseline.py` 新增
「豁免卫生检查」—— `allowed_violations` 每条**必须有非空 reason + 未过期的 expires**，
缺一即硬失败、过期按天报出。不做棘轮。**没有期限的豁免等于永久豁免，白名单会无声膨胀。**

### ⚠️ 刻意没跑 `--update`（重要）

它会把 `counts` 里**所有**键刷成当前值。而当前存在 2026-09-13 基线之后累积的
**未核实**结构漂移：AHK 101→100 文件 / 294→292 边 / 9→7 孤点；JS 5→6 文件 / 9→11 边。
其中 **JS 两项是放宽方向**。棘轮只收紧不放宽 —— 未核实前吸收进去，正是回归被藏起来的方式。

已先确认这些漂移**与 TD-010 无关**（图谱里 `AutoHotkey-2.0.26` 出现 0 次，
`EXCLUDE_DIRS`/`EXCLUDE_SEG` 都排除了该目录；基线 `generated_at = 2026-09-13` 早于本次改动）。
→ 只改违规相关字段，漂移继续 WARN 可见，另立 **TD-025**。

**阳性对照 5 组**：合法豁免（理由+未来期限）→ PASS；过期 → FAIL 报出天数；
非 ISO 日期 → FAIL；reason 空 → FAIL；允许集改回空集并重建 → 3 条 FAIL，还原回绿。

### 方法沉淀

- 判断「某条依赖违规是真违规还是白名单漏填」：看依赖是否**承重**（是否真的 use 了），
  以及方向是否符合分层。测试/夹具 crate 依赖被测代码永远是正确的。
- 更新图谱基线前，先确认待吸收的数字变化**来自哪次改动**；含「放宽方向」的必须逐项核实。
