## 五、TD-052 —— 时延断言偶发红（P1）

失败表现：保持时长 P95 实测 21.54ms > 上限 20.0ms；单独重跑 722 全绿。

成因实测确认是**宿主抢占**：离群点恰好落在 Windows 调度网格 15.625ms 上，且在 F1/F2/F3 上**均匀**分布、逐键中位数恒为 0.03ms —— 若是某个键的实现缺陷，该键分布会整体平移、中位数跟着走，实测没有。

**改两处，阈值一个未动**：
1. 采样窗口 3.2s → 6.4s，n 由 ≈54 提到 ≈107（P95 在 n≈54 时等价「第 3 大值」，n≈107 时等价「第 5 大值」）
2. 仍越界时重试一次，**只重试「中位数全过、仅 P95 兜底越界」**这一种宿主抢占签名；中位数失败 = 系统性漂移 = 真回归 → 立即失败、绝不重试

**否决「剔除离群点再算 P95」**：那等价于把 P95 降成更低分位（即放宽），或把兜底变成恒绿的空断言。

验证上的两点诚实处理：
- 合成负载 96 轮**未能稳定复现原失败**（3/48 vs 4/48，差异不显著），改用**注入同构签名**做确定性对照
- 阳性对照证明：`drift`（中位数失败）**不重试**、`tail`（可复现尾部回归）**重试后仍失败**

## 六之四、给 `src-tauri` 补了第一批测试（`30dd76a`）

`infrastructure/logging.rs` 原本 **0% 覆盖**。原因是 `init(app: &tauri::App)` 依赖真实 Tauri App，单测构造不了——**不是没写测试，是设计上不可测**。

但里面有个**写进文档注释却完全没守护的契约**：「默认 `info`，可用 `RUST_LOG` 覆盖」。把它抽成纯函数后即可测：

```rust
fn env_filter_from(log_spec: Option<&str>) -> EnvFilter {
    match log_spec {
        Some(spec) => EnvFilter::try_new(spec).unwrap_or_else(|_| EnvFilter::new("info")),
        None => EnvFilter::new("info"),
    }
}
```

**3 条测试 + 两组阳性对照**：

| 注入的回归 | 反应 |
|---|---|
| 默认级别 `info`→`warn` | 对应测试 **FAILED**，报出精确原因 |
| `unwrap_or_else`→`unwrap` | 非法 spec 那条 **FAILED** |

**实现时踩到的坑（clippy 直接阻断，值得记）**：新增 `fn` 的 `///` 文档块**不能与前一个函数的 `///` 首尾相接**——两段会被合并成同一份文档，导致前一个 `pub fn` 丢掉自己的文档（触发 `missing_errors_doc`），新的第一行又被当成上个列表项的续行。解法是把私有辅助函数与 `#[cfg(test)]` 放在**文件末尾**。

## 六之五、TD-054：`src-tauri` 是结构性盲区，补测试解决不了

**结论：不要再往 `src-tauri` 投入「补测试」的工作量** —— 实测证明投入产出比极低。

### 为什么解决不了

未执行的 **2124 个函数**里，绝大多数是 `generate_handler!` 为每个 Tauri 命令生成的**闭包**，以及 `run()` / `setup_ipc_callbacks()` 的**内部闭包**。**它们不是独立函数**，普通单元测试根本触达不到（`lib.rs` 23.65% 同属此类）。

### 已实测一条路，证实不通 —— 而且用对照组修正了归因

仅 dev 开启 `tauri` 的 `test` feature，拿到 `tauri::test::mock_app()`：

- ✅ **编译通过**
- ❌ **运行时报 `STATUS_ENTRYPOINT_NOT_FOUND`（0xc0000139）**

**第一次我差点把锅扣在 `tauri::test` 上。** 于是加了对照组重跑：

| 组 | 内容 | 结果 |
|---|---|---|
| **控制组** | `assert_eq!(1 + 1, 2)` —— **完全不碰 `tauri::test`** | ❌ 同样 0xc0000139 |
| **实验组** | `tauri::test::mock_app()` | ❌ 同样 0xc0000139 |

**结论修正**：问题**不在** `tauri::test`，而是**开启该 feature 后整个测试二进制无法加载**。控制组一行 `tauri::test` 都没调用也崩，说明是链接 / DLL 层面的问题。

**排除的假设**：怀疑 `target/debug/deps/asd_tauri_lib.dll`（cdylib 产物）被按名加载且版本不匹配——实测**挪走该 DLL 后仍然崩溃**，假设不成立。

**下一步若要做**：用 Dependencies / `dumpbin /imports` 定位缺失的具体符号——**不要再重复试 `tauri::test` 本身**。本次实验已完整回滚。

> 💡 **方法论**：环境类失败**先加对照组**。「A 功能跑不起来」和「加了 A 之后什么都跑不起来」是完全不同的两回事，不加对照很容易误判（这次就是靠对照组把排查方向整个扭转的）。

### 剩余选项（需决策）

1. 排查 `tauri::test` 的 DLL 依赖 —— 若解决，可批量给命令处理器补测试，**收益最大**
2. 改用 E2E 兜底 —— TD-016 已 9 suite / 53 用例全绿，但**记忆里记着「CI 上的 E2E job 从未真正跑过」**，只能本机跑，不能作为门禁
3. 接受现状 —— `src-tauri` 长期无覆盖率门禁，但文档已写清「G3f 的 89.05% **不是**全仓覆盖率」

⚠️ **方法论教训**：面对「覆盖率低」要分清三层 —— ① **没写测试**（补测试有用）② **不可测**（抽纯函数，如 `logging.rs`）③ **结构性不可达**（闭包/装配，只能换测试层级）。对症下药，别一律「补测试」。

## 六之八、TD-057：IPC 命令契约此前无门禁，已补 C8（契约断点靶点）

跨 AHK / Rust 边界的命令名靠两边**手写字符串**对齐：

```
Rust:  #[serde(rename = "toggle_group")]  ToggleGroup { ... }
AHK:   case "toggle_group":  CommandDispatcher._HandleToggleGroup(data, seq)
```

**此前没有任何东西校验二者一致。** 后果是：Rust 加一个变体而 AHK 忘了接——**编译期不报错**，只有运行时才吐「未知命令」；反过来 AHK 留个死分支也没人知道。当前 13 条刚好对齐（11 条走 `executor.ahk` 的 `Dispatch`，`ping`/`shutdown` 走 `ipc_client.ahk` 的 msgType 路径并另有防御性路由）——**纯属运气，没有守护**。

**已修**：`check-tech-debt.py` 新增 **C8：IPC 命令契约对齐**（硬失败、不做棘轮，与 C3/C4/C5/C6/C7 同类——守的是规则不是存量债）。

实现要点：

1. 取 Rust 侧 **`#[serde(rename)]` 的序列化名**，**不是变体名** —— 变体名是 PascalCase、线上字符串是 snake_case，拿变体名比对会全是假阳性
2. AHK 侧合并两处来源：`executor.ahk` 的 `Dispatch` 分支 + `ipc_client.ahk` 的 `ping` / `shutdown`
3. **双向校验**：Rust 有 AHK 没有、AHK 有 Rust 没有，都算失败
4. 任一侧解析不出内容即按失败处理，**不静默放过**

**阳性对照两组，正反两个方向都成立**：

| 注入 | C8 反应 |
|---|---|
| Rust 新增 `IpcCommand::ZzProbeAction`（rename=`zz_probe_action`） | 报「在 AHK 分发表里**没有对应分支**」→ FAIL |
| AHK 新增死分支 `zz_orphan_branch` | 报「在 Rust `IpcCommand` 里**没有对应变体**」→ FAIL |

还原后回绿（Rust 13 / AHK 13）。

⚠️ **踩到的坑**：新检查漏注册进 `main()` 的 `want` 集合，导致它**静默不执行**——第一次跑 C8 完全没有输出，我却差点以为它通过了。**不可见的检查等于没检查**；新增检查必须同步三处：函数本体、`cur` 字典、`want` 集合。
