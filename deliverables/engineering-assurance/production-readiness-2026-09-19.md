## 一、评估范围与前提假设

### 1.1 「生产级」在本报告中的定义

本项目是**面向个人用户的 Windows 桌面工具**（按键连招管理），**没有服务端、没有集群、没有值班团队**。因此本报告**没有套用 SaaS 生产标准**（不要求 Prometheus/Grafana/多可用区/99.9% SLO）。判定口径为：

> 一个从未见过本项目的**真实用户**，能否**装上 → 用起来 → 出问题时自救或被看见**；以及**维护者**能否**构建出包 → 发出去 → 出问题能回滚**。

### 1.2 评估边界

| 维度 | 负责人 | 主要手段 |
|---|---|---|
| 代码安全与健壮性 | Cody | 源码逐行 + 465 条测试实跑 |
| 架构与分发合规 | Archi | 配置取证 + md5 比对 + 许可证分析 |
| 可运维性 | Rex | 关键路径 grep + 故障恢复推演 + 预案批判性审阅 |

## 三、🔍 关键专项：GPLv2 合规的两问拆解法

这是本次评估中**推理最严密、也最容易搞错**的一处。Archi 与 Docu 二轮交叉后确定了正确的定性方式：

| | 问题 | 结论 | 独立性 |
|---|---|---|---|
| **Q1** | 分发 GPLv2 二进制，是否须随附许可证文本 + 源码说明？ | **确定：是** | **与 Q2 无关**。GPLv2 §2 的 mere aggregation 免除的是"另一件作品"，**不免除**你对被分发的 GPL 程序本身的 §1/§3 义务 |
| **Q2** | 自研 Rust/AHK 代码是否被传染、须以 GPL 开源？ | **不确定，需法务意见** | 量级远大于 Q1（答"是"则整个许可证策略重做） |

### 3.1 为什么这个拆解改变了行动

Docu 初稿把 GPL 定为「高」并附条件"若法律确认触发则升阻断"。**这个条件挂错了问题** —— 它会让读者以为"也许根本没义务"，从而**推迟那个最便宜的修复**（包内附许可证文本，约 1 小时），而该修复在 **Q2 两种答案下都必须要做**。

正确定性：**B2 定阻断，备注 Q2 需法务意见，二者独立不互相阻塞。**

### 3.2 取证链（Archi 实测，非推断）

- AHK 是 **vendored 而非 submodule**，181 个文件已入库（source 168 + sln/vcxproj 编译脚本）。
- 打包 exe 与 vendored 二进制 **md5 一致**（`52086b80…`），CI 现下载官方版 → **provenance 干净**。
- §3「源码物料」**其实已经齐备**（随公开仓库分发），**只差包内一句话说明**。
- Rust/AHK 是独立进程 + IPC、`build.rs` 无链接 → **大概率构成 mere aggregation，Rust 侧不被传染**（**推断**，建议法务优先复核；若推翻则许可证策略重做）。

### 3.3 结案（2026-09-19）

| 问 | 当时结论 | 现在的处置 |
|---|---|---|
| **Q1** | 确定：是 | **已做**：许可证文本 + 源码获取说明已进入 `bundle.resources`（§九 表 3–5） |
| **Q2** | 不确定，需法务 | **已被绕过而非被回答**：用户拍板项目自身采用 **`GPL-2.0-only`**（§九 表 6–10）。无论 Q2 答案是"传染"还是"不传染"，对外条款都是同一份 GPL-2.0，**该问题失去决策影响**。法务意见降为建议性 |

> **方法论收获**：Q2 是一个**高风险、长周期、且两种答案都不改变下一步动作**的问题。当初把它挂在 Q1 上（"若法律确认则升阻断"）差点让最便宜的修复被无限期推迟。**正确做法是把「无论答案如何都必须做」的那部分先摘出来做掉** —— 后来 Q2 又因为外部决策（选 GPL）而自动失效，说明当初为它等待是完全不值得的。

## 五、🟢 分域详判（含"超出预期"的正面记录）

### 5.1 代码安全与健壮性 —— 🟢 接近生产级（0 阻断 / 2 高危）

**实测数据**：465 条测试全绿（406 Rust + 59 前端）；生产代码 panic 点**仅 1 处**（`lib.rs:829` 入口 `expect`），**Tauri command 路径零 panic**。

**2 项高危**：
1. 看门狗重启 10 次失败后只写 error 日志、无前端事件（已并入 B4）。Cody 特别指出**项目里已有 `ipc:listener-failed` 的现成模式，照抄即可**，不需要新设计。
2. IPC 管道无 DACL（TD-071），同权进程可冒充 AHK —— **修复是一行代码**（见 §4 #2）。

**我派单时被纠正的两点**（记录以免后人重踩）：
- TD-072 **不是**路径遍历风险 —— `validate_file_path` 已拦住 `../`/UNC/相对路径，4 个入口全调用。真实缺口是"无根目录白名单 + 未 `canonicalize`"，且**这 5 条安全分支零测试覆盖**。
- CSP 在 `tauri.conf.json:22`，不在 `index.html`。
- 另：首次 `cargo test` 触发 rustc 1.95.0 ICE（**编译器 bug，非代码问题**），`CARGO_INCREMENTAL=0` 后正常。

### 5.2 架构可持续性 —— 🟡 接近生产级（0 架构阻断）

**超出预期的正面记录**：日志按天轮转 + 7 份保留 + 3 条契约测试、panic hook 清理子进程、IPC 心跳、IPC token 认证、dependabot 四类、cargo/npm audit 阻断 —— **全部到位**。

**无遥测不是缺陷**：对按键模拟工具而言，不做遥测是**正确选择**（Archi 明确判定），本报告不计为缺陷。
- **无 updater：中危，非阻断**（Archi 于 2026-09-19 **主动自我更正**：原判「高」→「低」，本报告采中位并移出阻断清单）。理由是研究稿把 updater 标为 **P2「按需评估」**，且同行并列提及的另外 3 个插件（global-shortcut / dialog / fs）**都已落地**，updater 是唯一未落地项 → 那一行是**评估清单而非承诺清单**。它是**发布成熟度问题**，应与「对外分发复查期」绑定触发，而非挂在阻断位。**真正阻断的是 B3（无 GitHub Release 步骤）**：无 updater 时手动重新下载是唯一升级路径，而这条路径的落点不存在。

**中危项**：
- **ADR 流程从未走完**（见 §4 #3）。
- **一处潜伏跨语言契约断点**：Rust 用 `keys[0]` 作身份键（`hotkey_merger.rs:31-32`），AHK 侧 `SendHotkeyEvent(keys*)` 是可变参，**当前生产未触发**，一旦触发即身份与载荷不一致。这是"IPC 无版本协商/无握手"的具体爆发点 —— 没有版本协商，这类不对称**只能靠"人工记得"来防**。
- **供应链合规无闸门**：有 `cargo audit` / `npm audit`（查 CVE，且阻断），但**无许可证合规扫描**（`cargo-deny` / `license-checker`）。安全与合规是两件事。
- CSP 放行 `'unsafe-inline'`：Archi 定为**可接受**（Tauri 前端是本地打包资源，攻击面远小于 Web），建议并入安全基线 ADR 而非单独立项。

### 5.3 测试与质量门禁 —— 🟢 单测接近生产级 / 🔴 端到端与发布不达标

### 9.2 B6 的两个反直觉点（都靠核实才没踩）

1. **「加载失败就通知用户」会引入回归。** `load_from_file_checked` 对「文件不存在」也返回
   `Err`（`ConfigLoadError::FileNotFound`），而**首次启动必然命中**。不加区分地弹窗，
   等于给每个新用户开局一个「你的数据丢了」的红色告警。正确判据不是「有没有出错」，
   而是「是不是正常路径」。已固化为纯函数 + 单测 + 阳性对照。
2. **这里不能用事件推送。** 配置在 `setup` 阶段加载，此时前端还没执行到 `init()`、
   监听器尚未注册，`emit` 的事件会**静默丢失**（正是本报告反复记录的「东西写了但没接上」）。
   改为前端启动后主动拉一次命令，行为可预期。

### 9.1 B4 的定性订正（本轮最有价值的一条反面教训）

原判「**执行器进入 Failed 终态后 UI 零提示**」的依据是：`grep getExecutorStatus / resetWatchdog` 在
`main.js` 与 `index.html` 里**零命中**。这个观察是**事实**，但推出的结论是**错的** —— 因为它默认了
「状态只能靠这两个符号传达」，而实际生效的是**推模式事件通道**：

```
watchdog.set_state(Failed)            watchdog.rs:416
  → lib.rs:225-246 轮询循环每 tick 比对 current != last_status
    → AppState::update_watchdog_state()   state.rs:343
      → emit "executor_status" {status, restartCount}
        → main.js onExecutorStatus → 圆点 .error（--danger 红）+ 文字「失败」
```

**同类错误的第二次变体**。本项目此前反复记的一条规矩是「东西写了，但没接上」（本报告 §四列了 11 处）；
而这一次是**它的镜像**：东西**早就接上了**，我却因为搜不到某个具体符号而判它没接上。
两条合起来才是完整的表述：**判断"有没有守护"和判断"已守护"一样，都必须落到实证，不能落到符号搜索。**
