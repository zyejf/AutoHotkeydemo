## 1. 复核结论：原注释错在哪

原注释（`ipc.rs`，已就地改写并保留证伪痕迹）称：

> `interprocess` 2.4.2 的 `ListenerOptions` 没有暴露安全描述符（DACL）设置入口，要限定「仅当前用户可连接」得绕过该库直接调 `CreateNamedPipeW`。

### 1.1 入口确实存在（读到源码）

`%USERPROFILE%\.cargo\registry\src\mirrors.ustc.edu.cn-38d0e5eb5da2abae\interprocess-2.4.2\src\os\windows\local_socket.rs:15-29`

```rust
pub trait ListenerOptionsExt: Sized + Sealed {
    fn security_descriptor(self, sd: SecurityDescriptor) -> Self;
}
impl ListenerOptionsExt for ListenerOptions<'_> {
    fn security_descriptor(mut self, sd: SecurityDescriptor) -> Self {
        self.security_descriptor = Some(sd);
        self
    }
}
```

它是 `os::windows` 下的**扩展 trait**（与平台无关的 `ListenerOptions` 分开），所以直接翻 `ListenerOptions` 的 inherent 方法看不到 —— 这大概就是当年写下原注释的原因。

### 1.2 在本项目配置下确实可用（不是「源码有但 cfg 不到」）

本项目配置：`interprocess = { version = "2.4.2", features = ["tokio"] }`，target windows，使用 `local_socket::tokio::{Listener, Stream}`。

完整透传链路（逐跳读源码确认）：

1. `src/local_socket/listener/options.rs:25` —— `ListenerOptions.security_descriptor: Option<SecurityDescriptor>` 字段（`cfg(windows)`）
2. `src/os/windows/local_socket/dispatch_tokio.rs:11` —— `listen()` → `options.create_tokio_as::<np_impl::Listener>()`（**tokio 路径也走这里**）
3. `src/os/windows/named_pipe/local_socket/tokio/listener.rs:27` —— `impl_options.security_descriptor = options.security_descriptor;` ← 关键一跳，tokio 路径没有丢字段
4. `src/os/windows/named_pipe/listener/create_instance.rs:51` —— `create_security_attributes(self.security_descriptor.as_ref().map(|sd| sd.borrow()), self.inheritable)`
5. 同文件 `:66` —— `CreateNamedPipeW(..., ref2ptr(&sa).cast_mut().cast())`，即 `lpSecurityAttributes`

**最终证据是实跑**：见 §4。

## 2. `SecurityDescriptor` 的构造 API 盘点

`src/os/windows/security_descriptor.rs` re-export 了 `as_security_descriptor / borrowed / ext / owned` 四个子模块。可用构造方式：

| 方式 | API | 评价 |
|---|---|---|
| **SDDL 反序列化** | `SecurityDescriptor::deserialize(&U16CStr)`（内部 `ConvertStringSecurityDescriptorToSecurityDescriptorW`） | ✅ **采用**。最省心，ACE 语义由 Windows 解析，不用手搓 ACL |
| 空壳 + 设 DACL | `SecurityDescriptor::new()` + `AsSecurityDescriptorMutExt::set_dacl(*mut ACL, bool)`（unsafe） | 需要先 `SetEntriesInAclW` 造 ACL，代码量和安全风险都更大 |
| 从既有对象克隆 | `AsSecurityDescriptorExt::to_owned_sd()` / `TryClone::try_clone()` | 不适用（我们要新建） |

**库自带方式够用，不缺东西**。唯一缺口是「当前用户 SID」得自己拿 —— 库只做安全描述符的搬运，不做身份查询，这是合理的职责边界。取 SID 用的是 `windows` crate 的 `OpenProcessToken` + `GetTokenInformation(TokenUser)` + `ConvertSidToStringSidW`。

`deserialize()` 内部走 `to_owned_sd()` → `try_clone::clone()`，会读 DACL/SACL/owner/group 四项；其中 ACL 缺失时 `GetSecurityDescriptor*Dacl` 仍返回 TRUE（用 `present` 标志区分），SID 缺失时 `clone_sid` 有显式的 null 分支，所以**只写 `D:` 不写 `O:`/`G:` 也能成功** —— 这点已由实跑验证（§4）。

设计取舍（都写进了代码注释）：

- **`GA`（GENERIC_ALL）而非精确权限**：AHK 侧 `ipc_client.ahk` 实际请求 `GENERIC_READ\|GENERIC_WRITE`（`0xC0000000`），`GA` 覆盖之。收回权限面需要同步 AHK 侧，收益不抵回归风险，本次不动。
- **失败 fail-open（退回默认 DACL）而非 fail-closed**：监听端建不起来 = IPC 彻底不可用且用户无感知，代价远大于退回默认 DACL；且退回后仍有随机管道名 + `ASD_AUTH_TOKEN` 首消息认证兜底。
- **保留 `(A;;GA;;;SY)`**：跨用户隔离的目标是把「别的人」挡在外面；SYSTEM 不是别的**人**，且服务/计划任务场景需要。已注明。

## 5. 阳性对照过程（注入故障 → 红 → 恢复 → 绿）

### 5.1 第一次：不是刻意注入，是初版本身就红

我接手时 `ipc.rs` 里已有一版实现（见 §8 并发说明），SDDL 为 `D:P(A;;GA;;;CO)(A;;GA;;;SY)`。跑测试：

```
test infrastructure::ipc::tests::test_ipc_listener_accepts_same_user_connection ... FAILED
  panicked: 同用户连接必须成功 —— 否则收紧 DACL 会把 AHK 子进程挡在门外，
            IPC 彻底不可用且用户无感知: 拒绝访问。 (os error 5)
test infrastructure::ipc::tests::test_security_descriptor_is_actually_enforced ... ok
```

**关键教训**：那条「DACL 是否生效」的阳性对照（SYSTEM-only → 必须拒）**通过了**，而「自家能不能连」**红了**。也就是说 —— 一个把所有人（含自己）都拒之门外的 DACL，同样能让「DACL 生效」类测试变绿。**只验证「拦得住」不验证「放得进自家」，等于没验证。** 这正是本项最大的回归风险点，也是我把 §4.2 真实子进程验证做掉的原因。

### 5.2 第二次：刻意注入故障，确认测试会红

把 `IPC_PIPE_SDDL_TEMPLATE` 改回 `"D:P(A;;GA;;;CO)(A;;GA;;;SY)"`，只跑 3 条相关测试：


## 7. 残留风险与未覆盖（不粉饰）

### 7.1 残留风险

1. **显式 DACL 挡不住「同一用户的其它进程」** —— SID 相同。TD-071 原始描述的主威胁（同权本地进程猜中管道名就能连）**仍由随机管道名 + `ASD_AUTH_TOKEN` 首消息认证承担**。这条已写进代码注释，防止后人误以为加了 DACL 就解决了冒充问题。
2. **fail-open**：取不到 SID 或 SDDL 解析失败时退回系统默认 DACL（仅 `warn!`）。若主理人认为应 fail-closed（宁可起不来也不降级），这是一行改动，但会引入「IPC 起不来且用户无感知」的新风险，建议维持现状。
3. **`(A;;GA;;;SY)`** 比「仅当前用户」宽一格，理由见 §3.2；若要更紧，删掉这一个 ACE 即可。
4. **真实 AHK 子进程验证是一次性的**（§4.2），没有常驻测试守着。若以后 SDDL 又被改成别的别名，只有测试 1/3 能拦，拦不到「AHK 侧参数变了」这类问题。
5. **未做跨用户 / 跨会话验证** —— 本机没有其他用户会话可测，「别的用户连不上」这条只由测试 2（SYSTEM-only）间接支撑。

### 7.2 AHK 子进程验证的复现脚本（未落库）

```ahk
#Requires AutoHotkey v2.0
pn := EnvGet("ASD_TEST_PIPE")
h := DllCall("CreateFileW", "Str", "\\.\pipe\" . pn, "UInt", 0xC0000000,
             "UInt", 0, "Ptr", 0, "UInt", 3, "UInt", 0x40000080, "Ptr", 0, "Ptr")
if (h = -1) {
    FileAppend("AHK-CONNECT-FAIL err=" . A_LastError, "*")
    ExitApp 1
}
DllCall("CloseHandle", "Ptr", h)
FileAppend("AHK-CONNECT-OK", "*")
ExitApp 0
```

用法：Rust 侧 `create_listener` 起监听端 → `AutoHotkey64.exe <此脚本>` 并注入 `ASD_TEST_PIPE=<管道名>` → 期待 exit 0 / stdout `AHK-CONNECT-OK`。
